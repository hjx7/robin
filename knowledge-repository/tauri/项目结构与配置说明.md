## 根目录文件说明

### package.json

定义项目依赖和 npm 脚本命令。关键部分如下：

```json
{
  "name": "mycubby",
  "private": true,
  "version": "0.1.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc --noEmit && vite build",
    "preview": "vite preview",
    "tauri": "tauri",
    "tauri:dev": "tauri dev",
    "tauri:build": "tauri build"
  },
  "dependencies": {
    "@tauri-apps/api": "^2.0.0",
    "@tauri-apps/plugin-shell": "^2.0.0",
    "vue": "^3.4.0"
  },
  "devDependencies": {
    "@tauri-apps/cli": "^2.0.0",
    "@vitejs/plugin-vue": "^5.0.0",
    "typescript": "^5.3.0",
    "vite": "^5.0.0",
    "vue-tsc": "^1.8.0"
  }
}
```

> 💡 Tauri 2.x 使用独立的插件包（如 `@tauri-apps/plugin-shell`），不再像 1.x 那样在核心包中包含所有 API。

### vite.config.ts

Vite 构建配置。关键是配置开发服务器端口，与 Tauri 配置保持一致：

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig(async () => ({
  plugins: [vue()],

  // Vite 选项
  clearScreen: false,
  server: {
    port: 5173,            // 开发服务器端口，需与 tauri.conf.json 中 devUrl 匹配
    strictPort: true,      // 端口被占用时直接报错
    watch: {
      // 忽略监听 src-tauri 目录，避免 Rust 文件变更触发前端重载
      ignored: ['**/src-tauri/**'],
    },
  },

  // 环境变量前缀（Tauri 特有的变量）
  envPrefix: ['VITE_', 'TAURI_ENV_*'],

  // 构建输出目录，需与 tauri.conf.json 中 frontendDist 匹配
  build: {
    outDir: 'dist',
    emptyOutDir: true,
  },

  // 路径别名
  resolve: {
    alias: {
      '@': '/src',
    },
  },
}))
```

## Tauri 后端目录 (src-tauri/)

### Cargo.toml

Rust 项目的依赖配置文件。关键内容：

```toml
[package]
name = "mycubby"
version = "0.1.0"
description = "MyCubby Tauri Application"
authors = ["you <you@example.com>"]
edition = "2021"
rust-version = "1.70"

[lib]
name = "mycubby_lib"
crate-type = ["staticlib", "cdylib", "rlib"]

[build-dependencies]
tauri-build = { version = "2.0", features = [] }

[dependencies]
tauri = { version = "2.0", features = [] }
serde = { version = "1", features = ["derive"] }   # JSON 序列化/反序列化
serde_json = "1"                                  # JSON 处理

# 👉 启用需要的官方插件
tauri-plugin-dialog = "2.0"                       # 对话框
tauri-plugin-notification = "2.0"                 # 系统通知
tauri-plugin-shell = "2.0"                        # 命令执行/打开外部链接
tauri-plugin-fs = "2.0"                           # 文件系统
tauri-plugin-os = "2.0"                           # 操作系统信息
tauri-plugin-http = "2.0"                         # HTTP 请求
tauri-plugin-store = "2.0"                        # 持久化存储
tauri-plugin-process = "2.0"                      # 进程管理

[profile.release]
panic = "abort"                    # 发生 panic 时直接终止
codegen-units = 1                  # 单代码单元编译，优化体积
lto = true                         # 链接时优化
opt-level = "s"                    # 优化体积
strip = true                       # 去除符号表
```

> 💡 Tauri 2.x 采用插件化架构，每个功能（对话框、文件系统等）都是独立的插件，需要单独声明依赖和启用。

### build.rs

Tauri 构建脚本，编译时执行，通常无需修改：

```rust
fn main() {
    tauri_build::build()
}
```

### icons/ 目录

存放各平台应用图标。标准图标尺寸：

| 文件 | 尺寸 | 用途 |
|------|------|------|
| `icon.png` | 1024x1024 | 源文件，用于 `tauri icon` 命令生成其他图标 |
| `32x32.png` | 32x32 | Windows/Linux 小图标 |
| `128x128.png` | 128x128 | Linux 图标 |
| `128x128@2x.png` | 256x256 | macOS 高分屏图标 |
| `icon.icns` | - | macOS 应用图标格式 |
| `icon.ico` | - | Windows 应用图标格式 |

**生成图标方法**：

准备一张 1024x1024 的 PNG 图片，然后运行：

```bash
pnpm tauri icon ./path/to/your-1024-icon.png
```

Tauri CLI 会自动生成所有尺寸和格式的图标。

### src/ 目录（Rust 源码）

#### src/main.rs - Rust 入口

```rust
// 关闭 Windows 控制台窗口（仅在 release 模式下）
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

fn main() {
    mycubby_lib::run()
}
```

#### src/lib.rs - 主库文件

```rust
// 导入自定义命令模块
mod commands;

// 导出命令函数供前端调用
use commands::greet;

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        // 👉 注册官方插件
        .plugin(tauri_plugin_dialog::init())
        .plugin(tauri_plugin_notification::init())
        .plugin(tauri_plugin_shell::init())
        .plugin(tauri_plugin_fs::init())
        .plugin(tauri_plugin_os::init())
        .plugin(tauri_plugin_http::init())
        .plugin(tauri_plugin_store::Builder::default().build())
        .plugin(tauri_plugin_process::init())

        // 👉 注册自定义命令（前端可通过 invoke 调用）
        .invoke_handler(tauri::generate_handler![
            greet,
            // 在此添加更多自定义命令
        ])

        // 👉 窗口创建钩子
        .setup(|app| {
            // 获取主窗口
            let _window = app.get_webview_window("main").unwrap();

            // 可在此进行初始化操作：
            // - 读取配置文件
            // - 启动后台任务
            // - 设置系统托盘

            Ok(())
        })

        // 启动应用
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

#### src/commands/mod.rs - 自定义命令模块

```rust
use serde::{Deserialize, Serialize};

// 👉 示例：一个简单的 greet 命令
// 前端可通过 invoke('greet', { name: 'World' }) 调用
#[tauri::command]
pub fn greet(name: &str) -> String {
    format!("Hello, {}! 欢迎使用 MyCubby!", name)
}

// 👉 示例：返回结构化数据的命令
#[derive(Serialize, Deserialize)]
pub struct AppInfo {
    name: String,
    version: String,
    platform: String,
}

#[tauri::command]
pub fn get_app_info() -> AppInfo {
    AppInfo {
        name: env!("CARGO_PKG_NAME").to_string(),
        version: env!("CARGO_PKG_VERSION").to_string(),
        platform: std::env::consts::OS.to_string(),
    }
}

// 👉 示例：异步命令（用于耗时操作）
#[tauri::command]
pub async fn heavy_computation(data: String) -> Result<String, String> {
    // 模拟耗时操作
    tokio::time::sleep(tokio::time::Duration::from_secs(2)).await;

    if data.is_empty() {
        Err("输入数据不能为空".to_string())
    } else {
        Ok(format!("处理完成: {}", data.to_uppercase()))
    }
}
```

### tauri.conf.json 关键字段详解

#### build 部分 - 构建相关配置

| 字段 | 说明 |
|------|------|
| `frontendDist` | 前端构建输出目录，Tauri 从此目录加载静态资源 |
| `devUrl` | 开发模式下前端开发服务器地址 |
| `beforeDevCommand` | 启动 `tauri dev` 前执行的命令（启动前端 dev server） |
| `beforeBuildCommand` | 执行 `tauri build` 前执行的命令（构建前端） |

#### app.windows 部分 - 窗口配置

可配置多个窗口，每个窗口有唯一的 `label` 标识：

```json
{
  "label": "main",                    // 窗口唯一标识，Rust/前端代码中通过此 label 获取窗口
  "title": "MyCubby",                 // 窗口标题
  "url": "/",                         // 窗口加载的前端 URL（相对前端 dist 目录）
  "width": 1200,
  "height": 800,
  "minWidth": 800,                    // 最小宽度
  "minHeight": 600,                   // 最小高度
  "maxWidth": 1920,                   // 最大宽度（可选）
  "maxHeight": 1080,                  // 最大高度（可选）
  "resizable": true,                  // 是否允许调整大小
  "minimizable": true,                // 是否可最小化
  "maximizable": true,                // 是否可最大化
  "closable": true,                   // 是否可关闭
  "fullscreen": false,                // 是否全屏启动
  "center": true,                     // 是否居中显示
  "x": 100,                           // 窗口 X 坐标（center=true 时忽略）
  "y": 100,                           // 窗口 Y 坐标
  "decorations": true,                // 是否显示系统标题栏和边框
  "transparent": false,               // 窗口背景是否透明
  "alwaysOnTop": false,               // 窗口是否始终置顶
  "alwaysOnBottom": false,            // 窗口是否始终置底
  "skipTaskbar": false,               // 是否不显示在任务栏/Dock 中
  "focus": true,                      // 是否获取焦点
  "visible": true,                    // 是否可见（可用于隐藏启动窗口，后再显示）
  "icon": "icons/icon.png"            // 窗口图标
}
```

> 💡 无边框窗口 (`decorations: false`) 需要自行实现标题栏、最小化/最大化/关闭按钮，详见 [核心概念](./core-concepts.md)。

#### app.security 部分 - 安全配置

```json
{
  "csp": null,                              // 内容安全策略，null 表示使用默认
  "capabilities": ["default"],              // 启用的权限配置（见 capabilities/）
  "assetProtocol": {                        // 自定义协议
    "enable": false,
    "scope": []
  }
}
```

**CSP (Content Security Policy)**：Tauri 默认开启严格的 CSP 策略。如果需要加载外部资源，需要修改：

```json
{
  "csp": "default-src 'self'; img-src 'self' asset: https://example.com data:; style-src 'self' 'unsafe-inline'; script-src 'self'"
}
```

#### capabilities/default.json ⭐ - 功能权限配置

Tauri 2.x 引入了 capabilities 机制，每个插件的 API 调用必须在此文件中显式声明权限：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "默认权限配置",
  "windows": ["main"],
  "permissions": [
    // ===== 核心权限 =====
    "core:default",

    // ===== Dialog 对话框权限 =====
    "dialog:allow-open",              // 允许打开文件/文件夹选择框
    "dialog:allow-save",              // 允许保存文件选择框
    "dialog:allow-message",           // 允许消息框

    // ===== Notification 通知权限 =====
    "notification:allow-notify",      // 允许发送系统通知
    "notification:allow-is-permission-granted",
    "notification:allow-request-permission",

    // ===== Shell 命令权限 =====
    "shell:allow-open",               // 允许打开外部链接/程序
    "shell:allow-execute",            // 允许执行系统命令（慎用！）
    "shell:allow-kill",
    "shell:allow-spawn",

    // ===== 文件系统权限 =====
    "fs:default",
    "fs:allow-read-file",
    "fs:allow-write-file",
    "fs:allow-read-dir",
    "fs:allow-create-dir",
    "fs:allow-remove-file",
    "fs:allow-rename-file",
    "fs:allow-exists",
    "fs:allow-copy-file",
    "fs:scope-home-file",             // 允许访问用户主目录文件
    "fs:scope-download-file",         // 允许访问下载目录
    "fs:scope-desktop-file",          // 允许访问桌面
    "fs:scope-document-file",         // 允许访问文档

    // ===== 操作系统权限 =====
    "os:default",
    "os:allow-os-info",               // 允许获取系统信息
    "os:allow-platform",
    "os:allow-version",
    "os:allow-family",

    // ===== HTTP 请求权限 =====
    "http:default",
    "http:allow-fetch",               // 允许发送 HTTP 请求
    "http:scope-api",                 // 允许访问指定 API 域名

    // ===== 持久化存储权限 =====
    "store:allow-get",
    "store:allow-set",
    "store:allow-has",
    "store:allow-delete",
    "store:allow-reset",
    "store:allow-save",
    "store:allow-load",

    // ===== 进程权限 =====
    "process:allow-exit",
    "process:allow-restart",

    // ===== 全局快捷键权限 =====
    "global-shortcut:allow-register",
    "global-shortcut:allow-unregister",
    "global-shortcut:allow-is-registered"
  ]
}
```

> ⚠️ **安全提示**：遵循「最小权限原则」，只声明确实需要的权限，尤其是 `shell:allow-execute` 和文件系统写入权限。

## 前端框架集成

### Vue 3 + TypeScript（推荐）

已在创建项目时选择 Vue 模板的情况下，安装常用依赖：

```bash
pnpm add vue-router@4 pinia
pnpm add -D @types/node
```

配置路由 `src/router/index.ts`：

```typescript
import { createRouter, createWebHashHistory } from 'vue-router'
import HomeView from '@/views/HomeView.vue'
import AboutView from '@/views/AboutView.vue'

const routes = [
  {
    path: '/',
    name: 'Home',
    component: HomeView,
  },
  {
    path: '/about',
    name: 'About',
    component: AboutView,
  },
]

const router = createRouter({
  history: createWebHashHistory(),  // 桌面端推荐使用 hash 模式
  routes,
})

export default router
```

pnpm add react-router-dom zustand
