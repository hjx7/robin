# Tauri 零基础 30 天学习路线图（从 0 到能独立上架桌面应用）

> 适用对象：不会 Rust、没写过桌面应用，只想用自己熟悉的前端（Vue/React/甚至原生 JS）做一个能打包安装的本地软件。每天投入 1.5-2 小时即可。
>
> 本文档配套同目录其他资料使用。每日任务标清楚了该读哪篇、在哪一步动手、做完要有什么可交付物。

---

## 0. 开始之前：你为什么选 Tauri

Tauri 不是 Electron 的平替，是另一条路。先把几个事实说在前面，省得你学了几天才发现不合适：

| 维度 | Tauri 2.x | Electron 30+ |
| :--- | :--- | :--- |
| 安装包体积 | 8-15 MB（用系统 WebView） | 120-200 MB（自带 Chromium + Node.js） |
| 内存占用 | 60-150 MB（和你开的浏览器标签差不多） | 250-600 MB（跑两个进程：Chromium + Node） |
| 后端语言 | Rust | Node.js（JavaScript） |
| 生态成熟度 | 官方插件够用，第三方少 | 几乎什么都能 npm install 到 |
| 跨平台 | Win 10 1809+/macOS 10.15+/Linux GTK4.1+ | Win 7+/macOS 10.13+/Linux 基本都能跑 |
| 安全模型 | 白名单 + scope + CSP，默认全锁 | 默认 Node 集成，关都关不干净 |
| 编译速度 | 第一次 10-30 分钟（下载 Rust 依赖） | 秒起 |
| 官方包管理分发 | 通过 Microsoft Store / App Store 正常上架 | 正常上架，但审核容易因为「体积过大」被拒 |

**你适合学 Tauri 吗？**

- ✅ 你要做的是工具类软件（文件处理、Markdown、笔记、截图、内网工具、家庭管理），不需要调用几十个 Node 原生模块
- ✅ 你特别在意安装包体积和内存占用，想让用户双击安装不后悔
- ✅ 你愿意花 1-2 周摸一点 Rust 基础，不要求自己写复杂后端
- ✅ 你准备上架到正规应用商店（国产商店对 Electron 体积越来越严）

**你还是选 Electron 吧：**

- ❌ 你重度依赖 ffmpeg、sqlite3、sharp 这类有 C++ 绑定的 Node 原生模块，且不想用 Rust 重写
- ❌ 你团队里没有任何人愿意碰 Rust，完全不敢学新语言
- ❌ 你要的是一周内上线一个 MVP，哪怕装个 200MB 也行
- ❌ 你需要兼容 Windows 7 / 老版本 macOS

## 1. 整体学习周期（30 天）

分四个阶段，循序渐进，每天的任务都有明确的"做完了能看到什么效果"。

| 阶段 | 天数 | 目标 | 每日产出 |
| :--- | :--- | :--- | :--- |
| **第一阶段：环境跑通** | 第 1-4 天 | Tauri 应用首次启动，窗口出现，能点按钮 | 第 2 天：`pnpm tauri dev` 成功，窗口显示欢迎页。第 4 天：打包一个能发给朋友的安装包 |
| **第二阶段：前后端打通** | 第 5-12 天 | 前端能调 Rust 命令、能收发事件、能读写本地文件 | 第 12 天：做一个「本地文件读写 Demo」，选文件→显示内容→保存回去，全流程跑通 |
| **第三阶段：原生能力** | 第 13-22 天 | 菜单、托盘、通知、对话框、拖拽、自动更新、全局快捷键 | 第 22 天：做一个「带托盘菜单的桌面便签」，关闭后主程序最小化到托盘 |
| **第四阶段：完整项目** | 第 23-30 天 | 做完一个能上架的练手项目，打包三个平台 | 第 30 天：输出三个安装包（Windows .msi / macOS .dmg / Linux .AppImage），能给别人装 |

1. 本文档 → 2. `环境搭建与快速入门.md` → 3. `01-首次跑通手把手.md` → 4. `项目结构与配置说明.md` → 5. `02-Rust零基础入门.md` → 6. `核心概念.md` → 7. `03-前后端通信专题.md` → 8. `前端开发指南.md` → 9. `后端 (Rust) 开发指南.md` → 10. `04-安全与权限专题.md` → 11. `05-原生能力专题.md` → 12. `06-三个练手项目.md` → 13. `构建、打包与部署.md` → 14. `最佳实践与常见问题.md` → 15. `07-常见报错排查与故障处理手册.md`

## 2. 每日任务详细拆解

### 第 1 天：环境铺底，不急着跑

**目标：** 把 Tauri 要求的所有依赖全部装完，跑 `tauri info` 全绿。

**你需要装什么（按顺序装）：**

1. **代码编辑器：VSCode**
   - 必须装的扩展：`rust-analyzer`（Rust 语法高亮+提示+错误跳转）、`Tauri-VSCode`（官方扩展，提供配置文件 JSON Schema 和提示）、`Error Lens`（让错误直接显示在行内，不用把鼠标移过去）、`Even Better TOML`（Cargo.toml 语法高亮）
   - 可选扩展：`Code Spell Checker`、`Prettier`、`ESLint`（前端常规三件套）

2. **Node.js 20 LTS**
   - Windows 用户推荐 nvm-windows（`nvm install 20 ; nvm use 20`）
   - macOS 用 Homebrew 装 nvm（`brew install nvm`）
   - 安装完 `node --version` 要输出 v20.x 以上

3. **包管理器（三选一）**
   - 推荐 pnpm（`npm i -g pnpm`），装依赖比 npm 快，省磁盘
   - 你一直用 yarn 也行，别一会 pnpm 一会 npm 混着来，node_modules 会炸

4. **平台专属的 C++ 构建工具（Windows 用户重点看）**
   - Windows：下载 [Visual Studio Build Tools 2022](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，安装时一定要勾 **「使用 C++ 的桌面开发」**，并勾选右侧明细里的 **Windows 10/11 SDK** 和 **MSVC v143**。这一步没选对，后面 Rust 编译直接报一堆看不懂的 link error。
   - macOS：`xcode-select --install`，弹窗口点安装，2-3 分钟
   - Linux（Ubuntu 系）：
     ```
     sudo apt update
     sudo apt install -y libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev libglib2.0-dev libgtk-3-dev
     ```
   - （Linux 装完别着急编译，把系统 update 一遍重启一次，有奇效）

5. **Rust 工具链**
   - Windows：[rustup.rs](https://www.rust-lang.org/tools/install) 下载 rustup-init.exe，运行后一路回车（选默认）
   - macOS/Linux：`curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`
   - 安装完**重新打开一个新的终端**（必须，因为环境变量刚写入）
   - 验证：`rustc --version ; cargo --version` 都有版本号

6. **（可选，国内用户强烈推荐）配置 Rust 国内镜像**
   - 新建文件 `%USERPROFILE%\.cargo\config.toml`（Windows）或 `~/.cargo/config.toml`（*nix）
   - 写入：
     ```toml
     [source.crates-io]
     replace-with = 'rsproxy'
     [source.rsproxy]
     registry = "https://rsproxy.cn/crates.io-index"
     [registries.rsproxy]
     index = "https://rsproxy.cn/crates.io-index"
     [net]
     git-fetch-with-cli = true
     ```
   - 不配置镜像的话，第一次 `tauri dev` 下载依赖可能要半小时，还可能中途失败

**第 1 天验收标准：**
- 打开 VSCode 装完上面 4 个扩展
- 在任意目录打开新终端，依次输入 `node -v`、`npm -v`（或 `pnpm -v`）、`rustc -V`、`cargo -V` 都不报错
- 如果上面 4 条都满足，今天任务完成，别着急创建项目，明天再说

### 第 2 天：创建第一个 Tauri 项目，把窗口跑出来

**目标：** 看到一个带「Welcome to Tauri!」的桌面应用窗口弹出来。

**操作（每一步照着敲，别改）：**

1. 打开终端，cd 到你准备放项目的目录，比如 `E:\projects`
2. 创建项目：`pnpm create tauri-app@2 my-first-app`
3. 交互式选项按这个选：
   - Project name · `my-first-app`
   - Choose which language to use for your frontend · **TypeScript / JavaScript**
   - Choose your package manager · **pnpm**（按你刚才装的那个）
   - Choose your UI template · **Vue**（React 用户选 React，不想学任何框架选 Vanilla）
   - Choose your UI flavor · **TypeScript**
   - Would you like to setup the Rust Tauri project now? · **Yes**
4. 创建完成后，进入目录：`cd my-first-app`
5. 安装前端依赖：`pnpm install`（这步 1-2 分钟）
6. 启动！`pnpm tauri dev`
7. 第一次启动**慢得离谱**，请耐心等。系统要做三件事：
   - 下载 Rust 的所有依赖 crates 包（大约 50-100 个包，配置了镜像的话 5-10 分钟，没配置 20-30 分钟）
   - 编译这些 Rust 依赖（6-15 分钟，CPU 会飙 100%）
   - 启动 Vite 前端开发服务器 + 打开 Tauri 窗口

**这段时间你要做什么：**
- 用 VSCode 打开 `my-first-app` 目录，把项目结构先翻一遍，看看每个文件大概是什么
- 对照阅读 [项目结构与配置说明.md](./项目结构与配置说明.md)，对照目录图一个个认识

**如果报错了怎么办：**
别慌，90% 的新手首次启动报错都是以下几类：

| 报错摘要 | 看哪里 |
| :--- | :--- |
| `link.exe` not found / LNK1181 / LNK2019 | VS Build Tools 没装好，回去重装「使用 C++ 的桌面开发」 |
| `Could not find webkit2gtk` / `WebView2 not installed` | Windows 老系统手动装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) |
| `cargo check` 一直卡着不动 | 没配置 Rust 国内镜像，回第 1 天第 6 步配置，或者耐心等 |
| `Port 5173 is already in use` | 关掉之前开的其他 Vite 项目，或改 vite.config.ts 里的 port |
| 其他看不懂的 Rust 编译错误 | 去 [07-常见报错排查.md](./07-常见报错排查与故障处理手册.md) 查，按报错关键字搜索 |

**第 2 天验收标准：**
- 桌面上弹出了一个 Tauri 窗口，标题是 `my-first-app`，页面显示 Welcome to Tauri
- 按 F12 能打开 DevTools，Console 里没有红色报错
- 在 VSCode 里改一下 `src/App.vue` 的一行文字，保存，窗口内容自动变了（热重载生效）

满足这三条，今天搞定。

### 第 3 天：改一改欢迎页，让前端和后端说话

**目标：** 自己写第一个命令，点按钮从 Rust 端拿一句动态问候语回来显示在界面。

**读配套资料：** [核心概念.md](./核心概念.md) 的「命令系统 Commands」一节（只看这一节，其他跳过）。

**动手：**
1. 打开 `src-tauri/src/commands/mod.rs`，在现有的 `greet` 函数下面自己写一个 `today_quote` 命令，随机返回一句名人名言（比如「苟日新，日日新，又日新」「千里之行始于足下」……共 5 句，Rust 端写 `vec![]` 用 rand 随机挑一句。rand crate 用 `cargo add rand` 加）
2. 在 `generate_handler!` 里注册 `today_quote`
3. 前端 `src/App.vue` 加一个「今日鸡汤」按钮，`onClick` 调用 `invoke('today_quote')`，把结果显示在按钮下方
4. 跑 `tauri dev`，点按钮看效果

**第 3 天验收标准：**
- 按钮能点，点了之后显示的名言每次不一样（或者十次里至少两次不一样）
- 控制台没有 invoke 报错（`Unhandled Promise Rejection: command not registered` 这种就是没注册命令）

### 第 4 天：第一次打包，发安装包给朋友

**目标：** 输出一个能发给朋友双击安装的 `.msi`（Win）/ `.dmg`（Mac）/ `.AppImage`（Linux）。

**读配套资料：** [构建、打包与部署.md](./构建、打包与部署.md) 的前三节。

**动手：**
1. 先准备一张 1024×1024 的 PNG 图标（找个免费图标网站下载），保存为项目根目录下 `app-icon.png`
2. 跑 `pnpm tauri icon ./app-icon.png`，Tauri CLI 会自动生成所有尺寸和格式的图标到 `src-tauri/icons/`
3. 跑 `pnpm tauri build`（第一次会做 release 编译，比 dev 慢一倍，做好等 15-30 分钟的准备）
4. 编译完成后，去 `src-tauri/target/release/bundle/` 目录找安装包：
   - Windows：`msi/xxx.msi` 或 `nsis/xxx-setup.exe`（推荐 NSIS 的 exe，用户双击安装体验好）
   - macOS：`dmg/xxx.dmg`
   - Linux：`appimage/xxx.AppImage`（文件本身是可执行的，`chmod +x` 后直接双击运行，不用装）
5. 把安装包拷到另一台没装过任何开发环境的电脑上（或者发朋友），让他装一下试试

**坑提醒：**
- Windows 用户第一次打包一般会提示「找不到 wix/nsis」，Tauri 会自动下载安装，点 Y 同意就行
- release 模式编译比 dev 慢是正常的，因为做了 LTO（链接时优化）和体积压缩
- 打包的安装包必须在对应平台上编译：Windows 只能打出 Windows 的包，macOS 只能打出 macOS 的包，没有交叉编译（别想省这一步）

**第 4 天验收标准：**
- 在另一台机器上安装成功，打开图标正常显示，运行不报错
- 安装包体积大致符合预期（Windows NSIS 一般 8-15MB，macOS dmg 一般 10-20MB）

### 第 5-8 天：Rust 零基础入门（够用就行，不用精通）

**目标：** 写 Tauri Commands 时不会懵，Rust 报错大概知道意思，能独立把常见命令写对。

**读配套资料：** [02-Rust零基础入门.md](./02-Rust零基础入门.md)，从头读到尾。

**每日分配：**
- 第 5 天：Rust 基本语法（变量、类型、函数、if/loop、struct、enum）
- 第 6 天：所有权与借用（最核心，花一整天啃都不亏）
- 第 7 天：错误处理（Result/Option）、集合类型（Vec/HashMap/String）、serde 序列化
- 第 8 天：最常用的第三方 crate（crate 就是 Rust 的 npm 包，相当于 node_modules）：rand、chrono、anyhow、thiserror、reqwest、tokio、serde_json

**每日动手题（做不出来别往前跳）：**
- 第 5 天作业：写一个 Rust 函数 `fn grade(score: u32) -> &'static str`，输入 0-100 的分数，返回「优秀」「良好」「及格」「不及格」
- 第 6 天作业：写一个函数 `fn first_word(s: &String) -> &str`，返回字符串第一个空格之前的切片（用借用和切片做，不能 clone 不能 to_string）
- 第 7 天作业：写一个函数 `fn safe_divide(a: i32, b: i32) -> Result<i32, String>`，除 0 返回 Err("不能除零")
- 第 8 天作业：用 chrono 取当前系统时间，格式化为「YYYY年MM月DD日 HH:mm:ss」，输出到控制台

**配套资源（有余力再看）：**
- [Rust Book 官方中文版](https://kaisery.github.io/trpl-zh-cn/)（最权威的 Rust 入门书，第 1-10 章值得读一遍）
- [Rust By Example 中文版](https://rustwiki.org/zh-CN/rust-by-example/)（代码驱动学习，适合不想看长篇大论的）
- [crates.io](https://crates.io/)（Rust 官方的 crate 仓库，找库就在这搜）

### 第 9-10 天：前后端通信全打通

**读配套资料：** [03-前后端通信专题.md](./03-前后端通信专题.md) + [核心概念.md](./核心概念.md) 的事件/窗口管理/状态管理三节。

**动手做：** 做一个「后台任务模拟」——前端点一个「开始处理」按钮，Rust 端循环 100 次 `sleep 50ms`，每 5 次通过 emit 向前端发一个 `progress` 事件，前端显示进度条到 100%，全部完成后弹一个对话框说「处理完成」。

**验收：**
- 点按钮后进度条动（不是一下满）
- 处理过程中 UI 不卡（说明异步命令写对了，没阻塞主线程）
- 全部完成后对话框弹得出来

### 第 11-12 天：文件系统实战

**读配套资料：** [前端开发指南.md](./前端开发指南.md) 里的文件系统插件一节 + [04-安全与权限专题.md](./04-安全与权限专题.md) 里的 fs scope 一节。

**动手：** 做一个完整的本地记事本：
1. 「打开」按钮，用 dialog 插件选一个 `.txt` 或 `.md` 文件
2. 用 fs 插件把文件内容读出来，显示在 `<textarea>` 里
3. 用户修改后点「保存」，用 save 对话框选路径，把 textarea 内容写回磁盘
4. 写个 scope 限制：只读/写用户的桌面和文档目录，不能写其他地方

**验收：**
- 打开/保存正常工作
- scope 生效：尝试在 C:\Windows\ 目录下保存时被系统拒绝（或你配置的 deny 路径）

### 第 13-15 天：系统托盘 + 自定义菜单 + 通知

**读配套资料：** [05-原生能力专题.md](./05-原生能力专题.md) 前 3 节。

**动手：** 给前几天的记事本加两个功能：
1. 应用启动后任务栏右下角有托盘图标，左键点击恢复窗口，右键弹出菜单（显示主窗口 / 新建文件 / 退出）

3. 顶部菜单栏加「文件」子菜单（新建/打开/保存/退出）和「帮助」子菜单（关于/快捷键说明），菜单项绑快捷键 Ctrl+N / Ctrl+O / Ctrl+S

### 第 16-18 天：拖拽、对话框、全局快捷键

**读配套资料：** [05-原生能力专题.md](./05-原生能力专题.md) 第 4-6 节。

**动手：**
1. 支持把本地 `.md/.txt` 文件直接拖进记事本窗口，自动加载内容（不用点「打开」）

### 第 19-22 天：自动更新 + 多窗口 + 持久化存储

**读配套资料：** [05-原生能力专题.md](./05-原生能力专题.md) 最后 3 节 + [核心概念.md](./核心概念.md) 状态管理一节。

**动手：**
1. 用 store 插件把记事本的「最近打开的文件列表」持久化到磁盘（应用关闭再打开，最近文件还在菜单里）
2. 做一个「设置」窗口，独立于主窗口，选项包括：字体大小、主题（亮/暗）、关闭窗口是否最小化到托盘。设置保存到 store。主题切换后主窗口和设置窗口都变

## 3. 学习中的几个心法

1. **Rust 不用学全。** 你写 Tauri 命令的时候，95% 的场景只用到：`struct`、`fn`、`String/&str`、`Vec`、`Result`、`#[derive(Serialize/Deserialize)]`、`tokio::time::sleep`、读写文件。剩下所有权借用，只要别写特别复杂的结构，基本够了。真遇到编译错误别死磕，报错信息写得非常清楚，`rust-analyzer` 会告诉你怎么改。
2. **前端部分跟你平时写网页一模一样。** 不要因为是 Tauri 桌面应用就觉得有什么不同，除了调用插件 API 之外，Vue/React/原生 JS 完全该怎么写怎么写。Tailwind、Pinia、Vite Router 全照常引入。
3. **报错先看终端和 DevTools。** Tauri 会把所有 Rust 的 panic 和编译错误直接打在 DevTools Console 里，红字写得明明白白，不用瞎猜。
4. **插件用多少装多少。** 官方 20 多个插件，不一定要全装。你用不到剪贴板就别装 clipboard-manager，用不到 HTTP 就别装 http，装的插件越少，安全配置越简单，体积也越小。
5. **第一次慢是正常的，以后就快了。** 第一次 `tauri dev` 慢、第一次 `tauri build` 慢，那是在下载和编译 Rust 依赖，之后改一行代码重编译就几秒钟。别因为第一次等了 15 分钟就放弃。
6. **官方文档 + Discord 是终极答案。** 遇到问题先在[官方文档](https://v2.tauri.app/zh-cn/)搜，中文文档目前覆盖 80%。找不到答案的话去 Tauri 官方 Discord 的 #help 频道问，核心维护者经常在线。
