# 07-常见报错排查与故障处理手册

> 本文按「报错信息 → 为什么会出 → 一步步怎么修 → 防坑 Checklist」的结构整理。全是群里新人最高频踩的 50+ 个坑，覆盖环境、编译、权限、通信、API、打包、发布 7 大类。遇到报错先 `Ctrl+F` 搜报错信息里的关键单词。

---

## 一、环境搭建期（刚装完就报错）

### E1. `Error: You must install the following dependencies first: MSVC / WebView2 / Rust / Node`（`create-tauri-app` 阶段）

**为什么：** 跑 `pnpm create tauri-app` / `npm create tauri-app@latest` 前，Tauri CLI 会先预检环境，缺哪个就报错。

**分步修：**
1. **缺 MSVC（Windows）：** 去 [https://visualstudio.microsoft.com/free-developer-offers/](https://visualstudio.microsoft.com/free-developer-offers/) 下载「Community 社区版」，安装时**勾选「C++ 桌面开发」工作负载**，单个组件里勾上「MSVC v143 + Windows 10/11 SDK」。装完重启终端再跑。
2. **缺 Rust：** 去 [https://rustup.rs](https://rustup.rs) 下 `rustup-init.exe`，全默认回车。装完开新终端执行 `rustc --version`，没输出版本号就再装一遍。
3. **缺 WebView2（Win10 旧版本）：** 去 [https://developer.microsoft.com/microsoft-edge/webview2/](https://developer.microsoft.com/microsoft-edge/webview2/) 下 Evergreen Standalone Installer（xxsetup.exe）双击装。Win11 自带不用管。
4. **缺 Node：** `node --version` 要求 ≥ 18。不够就去官网装 LTS。

### E2. `error: no default toolchain configured` / `'rustc' is not recognized...`

**为什么：** 你装了 rustup 但没实际装任何 toolchain（比如安装时选了 2 号选项 Customize），或者终端里 PATH 还没生效。

**修：**
```bash
rustup default stable-x86_64-pc-windows-msvc
# macOS Intel:
# rustup default stable-x86_64-apple-darwin
# macOS M系列:
# rustup default stable-aarch64-apple-darwin
rustc --version
```
还不行就把终端关掉开一个**新的**。PowerShell/CMD 老窗口 PATH 不会自动刷新。

### E3. `Updating crates.io index` 卡 10 分钟不动（中国大陆必踩）

**为什么：** 默认 cargo 从 GitHub 上拉索引 + 从 AWS CloudFront 下载 crate，大陆被限速到几 KB/s。

**修：用字节镜像 rsproxy.cn，5 秒搞定。**
1. Windows 在 `C:\Users\你的用户名\.cargo\config.toml`（没有就新建），Linux/macOS 在 `~/.cargo/config.toml` 里写：
```toml
[source.crates-io]
replace-with = 'rsproxy-sparse'
[source.rsproxy]
registry = "https://rsproxy.cn/crates.io-index"
[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"
[registries.rsproxy]
index = "https://rsproxy.cn/crates.io-index"
[net]
git-fetch-with-cli = true
```
2. 清缓存重新跑：
```bash
cd src-tauri
cargo clean
cargo fetch     # 应该飞快
```
3. `pnpm`/`npm` 太慢的话配 npm 镜像：`npm config set registry https://registry.npmmirror.com`

## 二、开发编译期（`pnpm tauri dev` 阶段）

### E4. `Command plugin:xxx|yyy not allowed. Your scope didn't include the specified URL or permission not enabled.`

**为什么：** 前端调用了某个插件 API，但 capabilities 里没开对应的 permission。Tauri 2.x 默认**所有插件 API 都关**。

**分步修：**
1. 先看报错里的命令名，比如：
   - `plugin:dialog|open` → 加 `"dialog:allow-open"`
   - `plugin:fs|read_file` → 加 `{ "identifier": "fs:allow-read-file", "allow": ["$DOCUMENT/**"] }`
2. 打开 `src-tauri/capabilities/default.json`，加到 `permissions` 数组里。
3. 等 Tauri dev 模式重新编译 capabilities（控制台会输出 `Reloading configuration`），不用重启 dev。
4. 实在不知道某个功能对应哪条 permission 名，搜 `v2.tauri.app/reference/capabilities/` 官方表。

### E5. `The scope for this url was not defined.`（dialog / fs / http）

**为什么：** permission 加了，但没写 `allow` scope，或者 scope 路径没配 `**`。例如你写了 `"allow": ["$DOCUMENT"]`，但 fs:allow-read-file 匹配的是**文件路径**，`$DOCUMENT` 本身是目录，所以匹配不上。

**修：** 所有目录 scope 结尾都加 `/**`：
```json
{
  "identifier": "fs:allow-read-file",
  "allow": ["$DOCUMENT/**", "$APP/**", "$DESKTOP/**"]
}
```
http 的要加域名 + `/**`：
```json
{
  "identifier": "http:allow-fetch",
  "allow": ["https://api.example.com/**", "https://*.example.cn/**"]
}
```

### E6. `Refused to connect to ... because it violates the following Content Security Policy directive: "connect-src 'self'"`

**为什么：** 前端 `fetch` / `axios` 请求了一个外部 API，但 `tauri.conf.json → app.security.csp` 的 `connect-src` 没把这个域名加进去。

**修：** CSP 里把你的后端域名加进去：
```json
{
  "app": {
    "security": {
      "csp": "default-src 'self' asset: ipc:; connect-src 'self' ipc: https://api.example.com https://other-api.cn"
    }
  }
}
```
**⚠️ 不要直接 `connect-src *`！** 安全专题 04 讲过为啥。

### E7. `Command xxx not found` / `error: builder` 阶段报错说命令没注册

**为什么：** 命令写了 `#[tauri::command]` 但没加到 `generate_handler![]` 数组里；或者命令名是 camelCase，前端 invoke 写了 snake_case（或反过来）。

**排查步骤：**
1. Rust 命令名：`fn hello_world()` → 前端 `invoke('hello_world', ...)` 用 snake_case。
2. 注册：`generate_handler![hello_world, list_todos, create_todo]`，逗号分隔，别漏。
3. 路径：命令写在子模块里的（比如 `commands::todo`），`generate_handler` 里要写全路径：`commands::todo::list_todos`，或者在 lib.rs 顶部 `use commands::todo::*;`。

### E8. `could not compile tauri-app v0.1.0` + Rust 报 50 个红色错误

**别恐慌，先看第一条错，其他都是连锁反应。** 99% 情况第一条就告诉你真正原因：

| 第一条错误常见内容 | 修法 |
| :--- | :--- |
| `cannot find struct, constant, or module X in this scope` | 缺导入。比如没写 `use serde::Serialize;`，或没装 crate：`cargo add serde --features derive` |
| `the trait bound X: Serialize is not satisfied` | struct 没加 `#[derive(Serialize)]` 或 `#[derive(Deserialize)]` |
| `private field X` / `field X of struct X is private` | struct 字段漏写 `pub`。所有要被 serde/Tauri 拿的字段必须 `pub` |
| `expected struct String, found &str` | 返回字符串前加 `.to_string()`，或用 `format!()` |
| `no method named xxx found for struct Y` | 缺 use 或缺 crate feature。比如 `.emit` 需要 `use tauri::Emitter;` |
| `binary \`cargo-xxx\` not found` | 缺工具：`cargo-binstall` 装对应工具，或用 `cargo install cargo-xxx` |
| `missing field pubkey for updater` / `unknown field windows-xxx` | `tauri.conf.json` 字段写错或版本不匹配。对照官方 schema：[https://v2.tauri.app/reference/config/](https://v2.tauri.app/reference/config/) |

### E9. `DevTools 打开后前端页面白屏 / 控制台一堆红色 404`

**为什么：** 你改了前端 `vite.config.ts` 端口但没改 `tauri.conf.json` → `app.windows[0].url`（dev 模式），或者 Vite 没启动成功。

**修：**
1. `tauri.conf.json` → `app.windows[0].url` 写的是 dev 用的 URL（通常是 `http://localhost:1420`，或 `vite` 默认的 `5173`）。必须跟你实际 `vite` 启动后终端显示的地址一致。
2. 也可以改成写 `"url": "/dist/index.html"` + devPath：
```json
{
  "app": {
    "frontendDist": "../dist",
    "devUrl": "http://localhost:1420",
    "withGlobalTauri": false
  }
}
```
3. 前端 build 产物位置 (`frontendDist`) 也要和 `pnpm build` 生成的目录一致（Vite 默认是 `../dist`，Next 是 `../out` 等）。

## 三、前端 invoke / 命令期

### E10. `TypeError: Cannot read properties of undefined (reading 'invoke')`

**为什么：** 在浏览器里直接开了 `http://localhost:1420`（不是 Tauri 桌面窗口），`@tauri-apps/api/core` 的 `window.__TAURI_INTERNALS__` 没注入，所有 API 全是 undefined。

**修：**
- 测试桌面逻辑必须用 `pnpm tauri dev` 打开的那个窗口，不是浏览器。
- 想让同一套代码既跑 Web 又跑桌面，做个 guard：
```ts
import { invoke as tauriInvoke } from '@tauri-apps/api/core'

export const isTauri = typeof window !== 'undefined' &&
  // @ts-ignore
  window.__TAURI_INTERNALS__ !== undefined

export const invoke = <T>(cmd: string, args?: any): Promise<T> => {
  if (!isTauri) {
    console.warn('[browser mock] invoke', cmd, args)
    return Promise.resolve({} as T)
  }
  return tauriInvoke<T>(cmd, args)
}
```

### E11. `Unhandled Promise Rejection: 'str' cannot be formatted` 或者命令直接抛 undefined

**为什么：** Rust 端 `#[tauri::command]` 返回值不是 `Result<T, E>`，而是直接 panic 了（`unwrap()` / `expect()` / `todo!()` / 数组越界），或 `println!("format {}")` 里参数个数不匹配。

**修：**
1. 所有命令**强制写成 `Result<T, String>`**，不要用 unwrap，用 `map_err(|e| e.to_string())?` 向上转。
2. Rust 终端（VSC 底部终端、dev 模式跑 tauri 的那个黑窗）会打印 `thread 'tokio-runtime-worker' panicked at xxx.rs:123:45:`。看那一行数字，90% 是 `unwrap()` on `None` 或 `Err`。
3. 永远不要在命令里写 `.unwrap()`，除非你就是想让用户闪退。

### E12. 参数总是 undefined / Rust 拿不到前端传的值

**为什么 90% 的情况：** 前端参数用了 camelCase，Rust 函数参数也写成 camelCase 但没有显式重命名。Rust 里变量必须是 snake_case，serde 自动按字段名匹配。

**修：**
```rust
// ❌ 错
#[tauri::command]
fn get_user(filePath: String) { /* ... */ }

// ✅ 对（1）：Rust 写 snake_case，前端也传 snake_case
#[tauri::command]
fn get_user(file_path: String) { /* ... */ }
// 前端：invoke('get_user', { file_path: 'C:/a.txt' })

// ✅ 对（2）：你硬要前端 camelCase，加 serde rename_all
#[derive(Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct Q {
    pub file_path: String,
}
// 现在前端传 { filePath: '...' } 也能匹配到 Rust 的 file_path 字段
```
> 简单规则：前后端约定好**统一一种命名法**，不然一半 bug 都在这种傻逼问题上。我推荐全 snake_case（Rust 风格）或全 camelCase + `#[serde(rename_all = "camelCase")]` 套在所有 struct 上（TS 风格）。

### E13. 大文件 `invoke('write_markdown', { content })` 超过 200KB 就失败

**为什么：** Tauri IPC 消息默认大小上限是 `10MB`（Tauri 2.x），但如果你传了 Base64 / 带很多转义字符的文本，序列化后会翻倍超出。或者 1.x 老项目只有 `1MB`。

**修：**
1. 简单方案（<50MB 文件）：改 `tauri.conf.json` 加大：
```json
{
  "app": {
    "ipc": { "maxMessageSize": 1073741824 }   // 1GB，最大不要超过 2GB
  }
}
```
2. **真正稳妥的方案（大文件推荐）：** 前端 `invoke` 只传路径 + 偏移 + 一次分片 4MB，分块写，不要一次塞 1GB。内存占用会从 2GB 降到 20MB。

## 四、fs / path / 路径相关

### E14. `The system cannot find the path specified. (os error 3)` / `No such file or directory (os error 2)`

**为什么 95% 情况：** Windows 上你写了反斜杠 `\` 没有转义，或者把 `$DOCUMENT` 当字符串拼了。

**修：**
- Rust 里**永远用 PathBuf.join**，自己不要拼字符串：
```rust
use std::path::PathBuf;
// ❌ 错
let p = format!("{}\\sub\\{}.md", doc_dir, name);
// ✅ 对
let p: PathBuf = [doc_dir.as_str(), "sub", &format!("{}.md", name)].iter().collect();
```
- 前端拿到的 WebView path（比如 `drop` 事件的 `/C:/Users/...`），先按 05 章拖拽那节「normalizeSlashesWin」去掉开头那个多的 `/`。

### E15. fs 权限明明开了，读某个文件还是 `scope not defined`

**为什么：** 你把路径传成了**带 `..` 的相对路径**（比如 `$APP/../../Users/.ssh/id_rsa`），Tauri scope 会在归一化之后再匹配，一旦归一化之后越出 allow 范围，就拒绝。

**修（安全专题 04 案例一再提一次）：**
1. Rust 后端重新归一化 + 验证前缀：
```rust
fn validate_in_dir(path: &str, allowed: &Path) -> Result<PathBuf, String> {
    let p = std::fs::canonicalize(path).map_err(|e| e.to_string())?;
    if !p.starts_with(allowed) {
        return Err("路径越界".into());
    }
    Ok(p)
}
```
2. 或者开 scope 时只放真的需要的目录，别把 `$HOME` 全开了。

### E16. macOS 上读不到 `~/Documents` 下的文件，弹系统隐私授权后还是不行

**为什么：** macOS 10.15+ 有「文件夹访问限制」。你的 .app 不是从 App Store 装的、没做签名公证，会遇到这个。

**修：**
1. 第一次读 Documents/Downloads 时会弹系统框，一定要点「允许」。
2. 没弹就手动给：系统设置 → 隐私与安全性 → 文件与文件夹 → 把你的 .app 勾上「文稿文件夹」「桌面文件夹」「下载」。
3. 做正式发布：用 Apple Developer ID 签名 + notarize（公证），用户就不会频繁弹授权了。

## 五、打包构建期（`pnpm tauri build`）

### E17. `error: failed to run custom build command for webview2-sys`（Windows）

**为什么 3 种常见原因：**
- A. 没装 Windows SDK 的「英语语言包」。VS Installer → Modify → 单个组件 → 勾选「Windows 10/11 SDK」+ 下面「Windows 10/11 SDK 英语」。
- B. 装了「Visual Studio Build Tools 2022」但没勾「C++ 桌面开发」。
- C. 之前装了旧版本 Build Tools / 旧 VS，环境变量 `VSINSTALLDIR` 指错了。

**快速验证：**
```bash
# 能输出一大串路径说明 VS 环境对的，没输出就是不对
where.exe cl.exe
```
没输出就回到 E1 修 C++ 环境。

### E18. `Signing command [signtool.exe / codesign] not found`

**为什么：** 你在 `tauri.conf.json` → bundle.windows/windowsSign 或 bundle.macOS/macosSigning 里开启了签名，但是没有签名证书/工具。

**修（开发阶段先关掉签名）：**
```json
{
  "bundle": {
    "windows": { "sign": null },
    "macOS":   { "signingIdentity": null }
  }
}
```
正式发布要签名：
- Windows：买一个 EV / OV Code Signing 证书（DigiCert/Sectigo），导入 `certmgr.msc` 或用 Azure Key Vault。
- macOS：Apple Developer Program 年费 99 刀 → 下载 Developer ID Application 证书到 Keychain。

### E19. `Updater pubkey not configured` 但我不想做自动更新

**为什么：** Tauri 默认加了 updater 插件模板，`bundle.updater.active: true`，但你没生成签名。

**修：** 直接关掉 updater：
```json
{
  "bundle": {
    "updater": { "active": false }
  }
}
```

### E20. 打包出来的 exe 有 200MB，说好的 Tauri 10MB 呢？

**为什么 4 个原因，按优先级：**
1. **debug symbols 没 strip**：默认 release 也带符号表，200MB 全是它。
2. **你在 Rust 里依赖了 `rustls-tls` + `openssl` + `webkit2gtk` 一堆重复 TLS 实现**。
3. **你把 `tauri-plugin-*` 20 个插件全加进来了，实际上只用了 3 个**。
4. **WSL/交叉编译产生了额外的 target**。

**修：`src-tauri/Cargo.toml` 里加 profile.release 优化，瞬间压到 5-8MB：**
```toml
[profile.release]
opt-level = "s"        # 优化体积
lto = true             # 链接时优化
codegen-units = 1      # 单代码生成单元，更慢但更小
panic = "abort"        # 去掉 panic 回溯信息（如果不需要定位线上问题的话）
strip = true           # 去掉调试符号
```
再跑 `pnpm tauri build`，Windows exe 通常 6-10MB，macOS app 10-15MB，这才是 Tauri 的真实实力。

## 六、原生能力期（菜单/托盘/更新/全局快捷键）

### E21. 托盘图标右键不弹菜单 / 左键点了没反应

**为什么 3 种常见：**
1. 图标文件路径错了。`Image::from_bytes(include_bytes!("../icons/tray.png"))` 里路径是相对于 `lib.rs` 的，不是相对于 workspace root。
2. macOS 把图标当成模板图但你的图不是模板图 → `.icon_as_template(false)`。
3. Windows 上图标必须是标准 16×16/32×32 的 PNG 或 ICO，SVG 不行，奇怪尺寸的 PNG 有些系统会直接忽略显示。

### E22. 全局快捷键注册失败（`global_shortcut register error`）

**为什么：** 快捷键组合被别的软件抢了。最常见：Ctrl+Alt+A 被微信、QQ、Snipaste、截图工具抢；Ctrl+Alt+S 被 PowerToys 抢；Win+任意被 Explorer 占用。

**修：**
1. 注册前先 `is_registered` 查一下，没注册成功就弹提示让用户自定义。
2. 不要选太通用的组合。Ctrl+Shift+Alt+字母（三修饰键）冲突率低很多。
3. 如果你的程序第二个实例打开了，快捷键也会注册失败。加 `single-instance` 插件，确保用户同时只能开一个。

### E23. 自动更新：下载完了没安装，重启还是老版本

**为什么：**
- Windows：运行中的 exe 被占用，MSI/NSIS 安装失败。`downloadAndInstall` 前先确保 `app.cleanup_before_exit()` + 自己退出。
- macOS：应用放在 `/Applications` 目录下才能被更新器写。你从 dmg 里直接双击运行 `.app`（只读 dmg），更新永远失败。**第一次发布的安装引导里要提醒用户「把应用拖到应用文件夹」。**
- Linux AppImage：更新器需要用户有可写权限。打包时把 `AppImageAllowExec` 权限 scope 配好。

## 七、用户电脑出问题（发布后用户反馈）

### E24. Win10 用户双击 exe 秒退，啥窗口都不弹

**90% 是 WebView2 Runtime 没装。** Win10 早期版本系统不带。

**修：**
1. 打包 `tauri.conf.json → bundle.windows.webviewInstallMode` 选 `"silent"` 或 `"offlineInstaller"`：
```json
{
  "bundle": {
    "windows": {
      "webviewInstallMode": {
        "type": "silent",
        "silentArgs": "/install /quiet /norestart"
      }
    }
  }
}
```
2. 或者 NSIS 安装器的 bootstrapper 就会在安装前帮用户静默装 WebView2，用户感知不到。
3. 在官网下载页加一行：「如果你是 Win10 且打不开，请先下载安装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)」。

### E25. 应用第一次启动要 10 秒+，之后秒开

**为什么：** Windows Defender / 360 安全卫士实时扫描。你第一次运行每个新 exe，它都要扫一遍签名+启发式。

**修（成本从低到高）：**
1. 给 exe 做 Windows 代码签名（OV/EV 证书），扫得更快。
2. 把安装路径放在 `Program Files` 下（默认 NSIS 就装这里），Defender 对受信任目录扫描少。
3. 真的很慢就加「启动画面 splashscreen」，`tauri.conf.json → app.windows[0].splashscreenImage: 'icons/splash.png'`，让用户有盼头。

### E26. 用户电脑内存占用越来越大，24 小时后从 80MB 涨到 1GB

**为什么 4 个高频：**
1. 前端 `listen()` 注册事件后组件卸载没调 `unlisten()`。Vue onUnmounted / React useEffect cleanup 忘写了。1 个事件监听占不了多少，但你每次路由切换都注册 10 个，一天就有几万个。
2. Rust 端 `tauri::async_runtime::spawn` 启的后台线程没退出条件，永远活着。
3. store 插件你没有 save，全在内存里越堆越多。
4. 前端大量用 `convertFileSrc` 把本地图片转 asset URL，没释放。这个是 Blob URL，记得 `URL.revokeObjectURL`。

## 八、通用排查套路（遇到陌生错误按这 5 步来，别上来就截图问人）

1. **第一条错误最珍贵：** Rust/Cargo 编译输出 50 条红，第一条永远是根因，后面 49 条是连锁反应。修完第一条重新跑，通常能消掉 80% 红。
2. **三端日志一起看：** ①Rust 终端 cargo 输出（红的）；②前端 DevTools Console（红的）；③前端 DevTools Network + Tauri IPC 面板（点开能看到每条 invoke 传了啥参数、返回啥错误）。
3. **最小复现：** 把 `#[tauri::command]` 里的逻辑一行一行注释掉，看是哪行炸的，90% 是最后一行你猜不到的代码。
4. **加 `.map_err(|e| e.to_string())?`，不要 `.unwrap()`。** 你所有 unwrap 的地方，将来总有一次会炸在用户电脑上，而且你找不到原因。
5. **Google 报错信息前半段 + site:v2.tauri.app + site:github.com/tauri-apps/tauri issues**，几乎 100% 你遇到的坑别人都报过，issue 底下官方给了修法。

## 九、终极救命 Checklist

每次改完代码打包之前，过一遍：

- [ ] 环境：rustup、node、pnpm/npm 版本对吗？Cargo config.toml 配镜像了吗？
- [ ] capabilities：所有用到的插件 permission 都开了吗？scope 都写 `**` 了吗？
- [ ] CSP：要 fetch 的域名加进 connect-src 了吗？script-src 没乱开 `unsafe-eval` 吧？
- [ ] 命令：都注册进 generate_handler 了吗？参数命名前后端一致吗？
- [ ] 错误处理：全是 `Result<T, String>` + `?`，没有 `.unwrap()` 吧？
- [ ] 路径：全用 PathBuf.join，没有手拼 Windows 反斜杠吧？
- [ ] 事件：前端组件卸载时 `unlisten()` 取消监听了吗？
- [ ] 打包：Cargo.toml `[profile.release]` 开了 strip + lto 了吗？
- [ ] 原生：托盘图标路径对吗？全局快捷键没冲突吧？
- [ ] 用户：发布说明里写了 Win10 需要 WebView2、mac 需要拖进 Application 了吗？

**这 10 条你全勾过，就不会再掉进 90% 的常见坑里。** 学 Tauri 的终极心法就 8 个字：「少用 unwrap，多看日志」。
