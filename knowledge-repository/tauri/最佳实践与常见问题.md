## 架构设计最佳实践

### 1. 前后端职责划分

| 放在前端 (WebView) | 放在 Rust 端 |
|-------------------|-------------|
| UI 渲染与交互 | 文件系统读写 |
| 状态管理（前端相关） | 复杂/耗时计算 |
| 表单校验（用户体验） | 数据安全校验 |
| 动画与过渡效果 | 数据库操作 |
| 轻量数据处理（< 100ms） | 加密/哈希/压缩 |
| 网络请求（简单场景） | 网络请求（带进度、重试、断点续传） |
| 内存中的数据 | 大量数据的持久化 |

> **原则**：如果是纯展示/交互逻辑，放前端；如果涉及系统资源、耗时操作、数据安全，放 Rust。

### 2. Command + Service 分层

推荐将 Rust 代码分为两层，避免命令层代码过于臃肿：

```rust
// ❌ 不好：命令里混着业务逻辑
#[tauri::command]
pub fn import_csv(path: String) -> Result<usize, String> {
    let content = std::fs::read_to_string(&path)
        .map_err(|e| e.to_string())?;
    let mut reader = csv::Reader::from_reader(content.as_bytes());
    let mut count = 0;
    for record in reader.records() {
        // ... 50+ 行业务逻辑
        count += 1;
    }
    // 保存到数据库...
    Ok(count)
}

// ✅ 好：命令只做参数校验和转发
#[tauri::command]
pub fn import_csv(state: State<AppState>, path: String) -> Result<usize, AppError> {
    if path.is_empty() {
        return Err(AppError::InvalidArgument("路径不能为空".into()));
    }
    // ⬇ 调用 service 层处理具体业务
    crate::services::import_service::import_csv(&state.db, &path)
}
```

### 3. IPC 调用的粒度控制

**避免**：
- ❌ 每个小操作都一次 invoke（按钮点击就 invoke 3-5 次）
- ❌ 单次 invoke 传几 MB 的 JSON

**推荐**：
- ✅ 将高频小操作合并为一个 invoke（批量操作）
- ✅ 大文件/大数据通过文件路径传递，不直接传输字节
- ✅ 前端 100ms 内多次调用用 debounce

```typescript
// ❌ 不好：每个条目单独调用
for (const file of files) {
  await invoke('process_file', { path: file })  // 1000 个文件 = 1000 次 IPC
}

// ✅ 好：批量调用，一次 IPC 处理多个
await invoke('process_files', { paths: files })
```

### 4. 事件与命令的选择

| 使用命令 (invoke) | 使用事件 (emit/listen) |
|------------------|------------------------|
| 需要返回值（获取数据） | 通知性质（后台进度、系统事件） |
| 请求-响应模型 | 单向通知、推送 |
| 主动触发的用户操作 | 多窗口/多组件共享状态变更 |
| 同步/异步都可以 | 纯异步 |

## 性能优化

### 1. IPC 性能

IPC（进程间通信）存在开销，序列化和反序列化需要时间。建议：

```
单次数据 < 64KB    : 正常 JSON 传输
64KB ~ 1MB         : 考虑使用二进制序列化（如 bincode），或拆分为多次
     > 1MB         : 避免 IPC 传输，改用文件路径传递 + 双方读写文件
```

如果需要高频传输数据流（如日志、实时监控），可以用 channel：

```rust
// Rust 端
use tauri::{ipc::Channel, Emitter};

#[tauri::command]
pub fn start_log_stream(app: AppHandle, rx: Channel<String>) -> Result<(), String> {
    tauri::async_runtime::spawn(async move {
        let mut i = 0;
        loop {
            tokio::time::sleep(Duration::from_millis(100)).await;
            let _ = rx.send(format!("[log {}] something happened", i));
            i += 1;
            if i >= 1000 { break; }
        }
    });
    Ok(())
}
```

```typescript
// 前端
import { Channel } from '@tauri-apps/api/core'

const channel = new Channel<string>()
channel.onmessage = (message) => {
  appendLogLine(message)  // 实时追加到 UI
}

await invoke('start_log_stream', { rx: channel })
```

### 2. 前端性能

桌面应用的 WebView 足够现代，但仍需注意：

- **长列表**：使用虚拟滚动（`vue-virtual-scroller` / `react-window`），不要渲染 1000+ DOM
- **频繁更新**：批量更新状态，避免每 16ms 内多次 setState
- **大文件预览**：图片/视频懒加载，不一次性解码
- **WebWorker**：复杂的数据处理放 Worker，不要阻塞 UI 线程
- **debounce/throttle**：搜索输入、窗口尺寸变化等事件限流

```typescript
// 简单的 debounce
export function debounce<T extends (...args: any[]) => any>(
  fn: T, delay = 300
): (...args: Parameters<T>) => void {
  let timer: ReturnType<typeof setTimeout> | null = null
  return (...args) => {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => fn(...args), delay)
  }
}

// 使用
const onSearch = debounce(async (keyword: string) => {
  results.value = await invoke('search', { keyword })
}, 250)
```

### 3. Rust 端性能

- 避免 `.clone()` 大对象，尽量使用引用
- 热路径使用 `Vec` 而不是 `HashMap`（如果数据量小）
- 字符串拼接用 `format!` 宏或 `String::with_capacity`
- 读文件用 `BufReader`，设大一点的 buffer
- JSON 反序列化/序列化避免重复操作，缓存解析结果
- 用 `cargo flamegraph` 定位热点：

```bash
# 在 Windows 上（需安装 flamegraph）
cd src-tauri
cargo flamegraph --bin mycubby
```

## 启动速度优化

Tauri 应用通常启动在几百毫秒内，以下方法可进一步加速：

### 1. 前端优化首屏

- **路由懒加载**：非首屏页面用 `() => import(...)` 动态引入
- **关键 CSS 内联**：`src/styles/main.css` 中首屏必需的样式不要拆分
- **减小首屏 JS**：检查构建后的 vendor chunk，按需拆分
- **Skeleton（骨架屏）**：在数据加载前显示占位，感知更快

### 2. Rust 端优化

- **配置优化**：在 `Cargo.toml` 的 `[profile.release]` 中：
  ```toml
  opt-level = 3    # 最高优化级别（s/z 是小体积，3 是快）
  lto = "thin"     # thin LTO 在编译速度和性能间平衡（fat 更慢但更好）
  codegen-units = 1
  ```
  如果启动速度比体积更重要，用 `opt-level = 3` + `lto = "thin"`

- **避免 setup 阻塞**：`setup` 函数中的初始化不要阻塞主线程
  ```rust
  .setup(|app| {
      // ✅ 好：耗时初始化放后台任务
      let handle = app.handle().clone();
      tauri::async_runtime::spawn(async move {
          let db = Database::open().await;  // 慢操作
          handle.manage(MyDb(db));
          handle.emit("db-ready", ()).ok();  // 通知前端
      });

      Ok(())
  })
  ```

- **延迟初始化插件**：不常用的插件不要在启动时初始化所有

### 3. 构建期优化

- 使用 PGO (Profile-Guided Optimization)：先运行一次收集使用数据，再针对性优化
  ```bash
  # 1. 构建带 PGO 插桩的版本
  RUSTFLAGS="-C profile-generate=target/pgo-data" cargo build --release

  # 2. 运行应用，模拟典型使用场景（打开窗口、执行操作）

  # 3. 合并 profile 数据
  cargo pgo merge target/pgo-data

  # 4. 使用 profile 重新编译
  RUSTFLAGS="-C profile-use=target/pgo-data/merged.profdata" cargo build --release
  ```

## 内存管理

### 前端内存

- **事件监听记得 unlisten**：
  ```typescript
  // ✅ 好：组件卸载时取消监听
  let unlisten: (() => void) | null = null
  onMounted(async () => {
    unlisten = await listen('some-event', handler)
  })
  onUnmounted(() => unlisten?.())
  ```

- **避免闭包持有大对象引用**
- **DevTools 的 Memory 面板** 录制 heap snapshot，排查内存泄漏
- **图片及时释放**：大量图片浏览时，离开页面把 `img.src = ''`

### Rust 端内存

- **使用 `Arc<Mutex<T>>` 还是 `Arc<RwLock<T>>`**？
  - 读多写少 → `RwLock`
  - 写多 → `Mutex`

- **及时 drop 大对象**：作用域结束时自动释放，或手动 `drop(x)`
- **避免内存泄漏**：循环引用使用 `Weak` 指针
- **内存 profiling**：用 `dhat`（Rust）或系统任务管理器监控

```toml
# Cargo.toml
[dependencies]
dhat = "0.3"
```

```rust
// main.rs（仅调试时启用）
fn main() {
    // 编译时通过 features 控制
    #[cfg(feature = "dhat-heap")]
    let _profiler = dhat::Profiler::new_heap();

    mycubby_lib::run()
}
```

## 安全最佳实践

### 1. Capabilities 只开必要的

```json
// ❌ 不好：简单粗暴全开
{
  "permissions": ["fs:default", "shell:default", "dialog:default"]
}

// ✅ 好：精确到每个 API，scope 限制路径
{
  "permissions": [
    {
      "identifier": "fs:allow-read-file",
      "allow": ["$DOCUMENT/MyCubby/**", "$DESKTOP/**"],
      "deny": ["$DOCUMENT/MyCubby/secrets/**"]
    },
    {
      "identifier": "fs:allow-write-file",
      "allow": ["$DOCUMENT/MyCubby/**"]
    },
    "dialog:allow-open",
    "dialog:allow-message"
  ]
}
```

### 2. 严格校验前端传入数据

```rust
#[tauri::command]
pub fn read_file(state: State<AppState>, path: String) -> Result<String, AppError> {
    // 1. 路径遍历攻击防护
    let canonical = std::fs::canonicalize(&path)
        .map_err(|_| AppError::NotFound(path.clone()))?;

    let allowed = state.allowed_dir.lock().unwrap();
    if !canonical.starts_with(&*allowed) {
        return Err(AppError::PermissionDenied(
            "路径不在允许范围内".into()
        ));
    }

    // 2. 文件大小限制（防止读取几 GB 大文件卡死）
    let meta = std::fs::metadata(&canonical)?;
    if meta.len() > 50 * 1024 * 1024 {  // 50MB
        return Err(AppError::InvalidArgument(
            "文件过大，最大支持 50MB".into()
        ));
    }

    // 3. 文件类型白名单
    let ext = canonical.extension()
        .and_then(|e| e.to_str())
        .unwrap_or("");
    if !["txt", "md", "json", "csv"].contains(&ext) {
        return Err(AppError::InvalidArgument(
            "不支持的文件类型".into()
        ));
    }

    Ok(std::fs::read_to_string(&canonical)?)
}
```

### 3. CSP 策略收紧

生产环境使用严格的 CSP，不要直接 `csp: null`：

```json
{
  "app": {
    "security": {
      "csp": "default-src 'self'; img-src 'self' asset: data: https://img.mycubby.com; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self' https://api.mycubby.com; font-src 'self' data:; frame-ancestors 'none'; form-action 'none'"
    }
  }
}
```

### 4. Shell 执行极度危险

如果必须执行系统命令：

- **只允许白名单命令 + 固定参数组合**
- **绝不把前端传入的字符串拼到命令中**
- **用 `Command::new("xxx").arg(...).arg(...)` ，不要用 `sh -c`**
- **输出结果做大小截断**

```rust
use std::process::Command;

// ✅ 好：写死命令，参数严格校验
#[tauri::command]
pub fn open_in_explorer(path: String) -> Result<(), AppError> {
    let p = std::fs::canonicalize(&path)?;

    // 只允许打开允许目录下的路径
    if !p.starts_with(ALLOWED_ROOT.as_path()) {
        return Err(AppError::PermissionDenied("无权限".into()));
    }

    // 固定命令，参数通过 .arg() 传入（无 shell 注入风险）
    if cfg!(target_os = "windows") {
        Command::new("explorer")
            .arg("/select,")
            .arg(&p)
            .spawn()?;
    } else if cfg!(target_os = "macos") {
        Command::new("open").arg("-R").arg(&p).spawn()?;
    } else {
        Command::new("xdg-open").arg(p.parent().unwrap_or(&p)).spawn()?;
    }

    Ok(())
}
```

### 5. 不要把密钥写在前端

前端代码打包后可被反编译，**任何 API Key、密码、Token 都不要写在前端**。

- ✅ 放在 Rust 端（编译进二进制）
- ✅ 更好：放在环境变量/配置文件，运行时读取
- ✅ 最安全：加密保存，使用时提示用户输入密码解密

## 调试技巧

### 1. 调试 Rust 代码

**使用 VS Code + CodeLLDB**：

1. 安装 `vadimcn.vscode-lldb` 扩展
2. 创建 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug Tauri App",
      "type": "lldb",
      "request": "custom",
      "targetCreateCommands": [
        "target create ${workspaceFolder}/src-tauri/target/debug/mycubby.exe"
      ],
      "processCreateCommands": [
        "settings set target.run-args",
        "process launch"
      ],
      "preLaunchTask": "build-tauri-debug"
    }
  ]
}
```

创建 `.vscode/tasks.json`：

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "build-tauri-debug",
      "command": "cargo",
      "args": ["build", "--manifest-path", "${workspaceFolder}/src-tauri/Cargo.toml"],
      "type": "process",
      "group": "build",
      "problemMatcher": "$rustc"
    }
  ]
}
```

然后：
- 在 Rust 源码行号左侧点击设置断点
- 按 F5 开始调试

### 2. 调试前端代码

开发模式下直接按 F12 / Ctrl+Shift+I 打开 DevTools，和普通网页完全一致：
- Console 看日志
- Network 看 fetch/axios
- Source + Source Map 下断点
- Application / Storage 看 Store/LocalStorage

### 3. 调试生产版本

构建 debug 版的 release bundle：

```bash
pnpm tauri build --debug
```

产物在 `src-tauri/target/debug/bundle/`，包含符号表，崩溃时能显示行号。

### 4. 打开 DevTools（生产版本）

如果需要排查用户环境的问题，生产版默认禁用 DevTools，可做个隐藏入口：

```rust
// lib.rs
use tauri::WebviewWindowExt;

pub fn run() {
    tauri::Builder::default()
        .setup(|app| {
            let window = app.get_webview_window("main").unwrap();

            // 调试开关：按 Ctrl+Shift+F12 打开 DevTools
            let w = window.clone();
            window.on_window_event(move |e| {
                if let tauri::WindowEvent::KeyboardInput { event, .. } = e {
                    if event.state == tauri::KeyState::Pressed
                        && event.logical_key.to_text() == Some("F12")
                    {
                        // 在实际代码中检查 modifier
                        let _ = w.open_devtools();
                    }
                }
            });

            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error");
}
```

### 5. 收集崩溃日志

```rust
// main.rs
fn main() {
    // 注册 panic hook
    std::panic::set_hook(Box::new(|panic_info| {
        let backtrace = std::backtrace::Backtrace::force_capture();
        let msg = format!(
            "Panic: {}\nBacktrace:\n{:?}",
            panic_info, backtrace
        );
        eprintln!("{}", msg);

        // 写入崩溃日志文件
        if let Ok(dir) = tauri::api::path::app_log_dir(
            &tauri::generate_context!().config()
        ) {
            let _ = std::fs::create_dir_all(&dir);
            let ts = chrono::Local::now().format("%Y%m%d_%H%M%S");
            let _ = std::fs::write(dir.join(format!("crash-{ts}.log")), msg);
        }
    }));

    mycubby_lib::run()
}
```

### 6. 环境检测辅助

快速判断问题出在哪一层：

```vue
<script setup lang="ts">
import { onMounted, ref } from 'vue'
import { invoke } from '@tauri-apps/api/core'

const diagnostics = ref({
  isTauri: false,
  platform: 'web',
  arch: '',
  rustVersion: '',
  invokeLatency: 0,
})

onMounted(async () => {
  // 检测是否在 Tauri 中运行
  diagnostics.value.isTauri = '__TAURI_INTERNALS__' in window
  if (!diagnostics.value.isTauri) return

  // 测量 IPC 延迟（空命令往返时间）
  const t0 = performance.now()
  for (let i = 0; i < 100; i++) await invoke('noop')
  diagnostics.value.invokeLatency = Math.round((performance.now() - t0) / 100)

  diagnostics.value.rustVersion = await invoke('get_rust_version')
})
</script>
```

## 常见问题 FAQ

### Q1: 首次 `tauri dev` 编译很慢怎么办？

**正常现象**。Rust 首次编译所有依赖需要几分钟到十几分钟（取决于网络和 CPU），之后都会有缓存，二次编译通常只需几秒。

加速方法：
- 配置 `[source.crates-io]` 国内镜像（rsproxy、字节等）
- 确保项目路径不包含中文、空格（Windows 下会影响部分 crates）
- SSD 磁盘 + 足够内存（>= 16GB）

### Q2: 运行 `tauri dev` 报错 "Running `... cargo ...` failed"

通常是 Rust 依赖下载/编译失败：

1. 尝试手动：
   ```bash
   cd src-tauri
   cargo clean
   cargo check  # 看具体是哪个 crate 报错
   ```
2. 如果是网络问题，配置 crates.io 镜像
3. 如果是 MSVC 报错，确保安装了 "Desktop development with C++" 且组件完整
4. Windows 下路径过长：把项目移到 `C:\dev\MyCubby` 这样的短路径

### Q3: 开发时窗口白屏/加载失败

检查 `tauri.conf.json` 中：
- `build.devUrl` 是否和 Vite 实际监听地址一致（默认 http://localhost:5173）
- Vite 配置中 `server.strictPort = true`，避免端口被占用自动换到 5174
- 看 Rust 控制台输出的报错，一般会有 CSP 或资源路径问题
- 如果是路由刷新白屏，把路由改成 **hash 模式**

### Q4: `tauri build` 前端资源找不到

确保 `frontendDist` 设置正确。标准 Vite 项目是 `../dist`，如果改了 Vite 的 `build.outDir` 要同步改。

检查顺序：
```
1. 手动 pnpm build，看 dist/ 里有没有 index.html
2. 打开 dist/index.html 确认脚本/样式路径是相对路径（/assets）
3. 检查 vite.config.ts 中没有设置 base: '/some/path/' （应该是 './' 或 '/'）
```

### Q5: invoke 命令找不到

错误：`Command XXX not found`

检查：
1. `#[tauri::command]` 宏已加在函数上
2. 已在 `generate_handler![...]` 中列出函数名
3. 函数是 `pub fn` 或在同一模块
4. 拼写、大小写：前端用的是 `snake_case`（和 Rust 一致）

### Q6: Windows 安装包被 SmartScreen 拦截

这是正常的安全机制，不是你的程序有问题：

- **短期方案**：告诉用户点击「更多信息」→「仍要运行」
- **中期方案**：购买 OV 代码签名证书，签名后使用几个星期后 SmartScreen 会建立信誉
- **最优方案**：购买 EV 代码签名证书，签名后立即获得 SmartScreen 信任

### Q7: 打包的 exe 被杀毒软件报毒

- 杀毒软件对「未签名的可执行文件 + 压缩壳」非常敏感
- **不要用 UPX** 压缩（UPX 是误报重灾区）
- 用官方插件和依赖，不要用冷门的 crate
- **签名**是目前最有效的降低误报的办法
- 提交到 Microsoft / 360 / 腾讯管家等进行误报申诉

### Q8: macOS 打开应用提示「已损坏，移到废纸篓」

Gatekeeper 拦截了未签名/公证的应用。解决：

1. 临时：右键 → 打开（第一次绕过，之后可直接开）
2. 用户终端执行：
   ```bash
   xattr -dr com.apple.quarantine /Applications/MyCubby.app
   ```
3. 发布方：用 Apple Developer 证书签名 + 公证后再发布

### Q9: 读取本地图片/视频显示损坏

- 不要直接 `<img src="C:/path.png">`，WebView 不能直接访问本地文件系统
- 正确做法：用 `convertFileSrc()` 转成 Tauri 协议 URL
  ```typescript
  import { convertFileSrc } from '@tauri-apps/api/core'
  const url = convertFileSrc('C:/path.png')
  // 得到类似: http://asset.localhost/path?...&v=1
  ```

### Q10: 前端使用 fetch / axios 报 CORS / 混合内容错误

Tauri 2.x 前端 origin 是 `http://localhost`（生产版是 `https://tauri.localhost`），如果后端 API 没有对应 CORS 头：

1. 推荐：使用 `@tauri-apps/plugin-http` 替代浏览器 fetch（绕过 CORS）
2. 或后端 API 返回 CORS 头：`Access-Control-Allow-Origin: *` 或针对你的 origin

### Q11: Rust 异步命令中用 `reqwest` 阻塞/死锁

不要使用 `reqwest::blocking`，必须用 `reqwest` (async) 的 Client。异步命令运行在 tokio 运行时中，阻塞 API 会卡住整个线程池。

### Q12: 打包后 Windows 7 打不开

Tauri 2.x 依赖 WebView2，**不支持 Windows 7**。最低支持 Windows 10 1809。

如果必须支持 Windows 7，需要降级到 Tauri 1.x + 旧版 EdgeHTML（不推荐）。

### Q13: 窗口关闭后进程还在

你的 `tauri.conf.json` 中如果设置了 `exitOnCloseWindow: false` 或创建了隐藏窗口，程序不会自动退出。

修复：确保最后一个窗口关闭时退出：

```rust
use tauri::Manager;

pub fn run() {
    tauri::Builder::default()
        .on_window_event(|window, event| {
            if let tauri::WindowEvent::CloseRequested { .. } = event {
                // 关闭最后一个窗口时退出
                let app = window.app_handle();
                if app.webview_windows().len() == 1 {
                    app.exit(0);
                }
            }
        })
        .run(tauri::generate_context!())
        .expect("error");
}
```

### Q14: 跨平台路径处理踩坑

Windows 用 `\`，Linux/macOS 用 `/`，且 Windows 有盘符前缀。

**永远不要手动拼路径字符串！** 使用：
- Rust：`PathBuf::join()`、`std::path::Path`
- 前端：`@tauri-apps/plugin-path` 的 `join()`、`normalize()`
- 展示给用户的路径：可以把 `\` 统一显示为 `/`

```typescript
// ✅ 好
import { join, documentDir, basename, extname } from '@tauri-apps/plugin-path'
const path = await join(await documentDir() || '.', 'MyCubby', 'data.json')

// ❌ 不好
const path = `${await documentDir()}\\MyCubby\\data.json` // 仅 Windows 能用
```

### Q15: Tauri 1.x 升级到 2.x 迁移要点

| 1.x | 2.x |
|-----|-----|
| `@tauri-apps/api/shell` | `@tauri-apps/plugin-shell` |
| `@tauri-apps/api/fs` | `@tauri-apps/plugin-fs` |
| `@tauri-apps/api/dialog` | `@tauri-apps/plugin-dialog` |
| `@tauri-apps/api/notification` | `@tauri-apps/plugin-notification` |
| `allowlist` 配置 | `capabilities/*.json` 权限声明 |
| `window.create` API | `WebviewWindowBuilder`（两端都可以）|
| `updater` 内置 | `tauri-plugin-updater` |

**迁移最佳步骤**：
1. `pnpm add @tauri-apps/api@2 @tauri-apps/cli@2`
2. 逐个安装用到的 `@tauri-apps/plugin-xxx`
3. `cargo update -p tauri`
4. 运行 `cargo check` 逐个修复编译错误
5. 参照 [官方迁移指南](https://v2.tauri.app/start/migrate/from-tauri-1/) 对照每一条变更

## 总结

Tauri 2.x 给了我们极轻量的桌面端开发体验，配合 Vue/React 等成熟前端生态，可以快速产出高质量跨平台应用。开发时记住三个关键词：

- **安全优先**：最小权限、参数校验、禁止命令拼接
- **性能意识**：控制 IPC 粒度、异步化耗时操作、冷启动优化
- **分层设计**：命令层 (commands) 薄，业务层 (services) 厚，便于测试和维护
