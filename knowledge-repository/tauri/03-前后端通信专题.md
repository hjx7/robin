# 03-前后端通信专题：命令、事件、状态、多窗口

> 本文把 Tauri 前后端通信的四种机制，每种都配**完整的最小可运行代码**（Rust 端 1 段、TS 端 1 段，复制粘贴就能跑通）。读完，你应该能独立完成以下需求：「前端点按钮让 Rust 批量处理文件，处理中实时弹进度，处理完开一个独立的结果窗口，所有窗口共享同一份配置状态」。

---

## 0. 一张表先看清楚四种通信机制分别什么时候用

| 机制 | 简称 | 方向 | 有没有返回值 | 适合场景 |
| :--- | :--- | :--- | :--- | :--- |
| **Commands（命令）** | `invoke` | 前端 → Rust | 有（Promise<T>） | 一问一答：调 Rust 做一件事，做完拿结果回来。90% 的场景用这个。 |
| **Events（事件） Rust 发** | `emit` + `listen` | Rust → 前端 | 没有 | 后台任务实时推进度、后端状态变了通知、异步回调 |
| **Events（事件） 前端发** | `emit` + `listen` | 前端 → Rust | 没有 | 不需要返回值的「广播通知」：切换了主题、刷新了列表 |
| **State（全局状态）** | `State<T>` 参数 | Rust 内部跨命令共享 | 不直接通信 | 多命令共享内存数据：比如数据库连接池、当前用户、配置文件 |
| **多窗口消息** | `emitTo` + 对应窗口 `listen` | 窗口 ↔ 窗口 | 没有 | 设置窗口改了配置，通知主窗口立刻换主题 |

> ⚠️ 90% 的新人会犯一个错误：把 invoke 当万能工具，明明是一个进度推送场景，非要轮询 invoke 100 次问「完了吗？多少了？」。不要这么干，用事件。

---

## 1. Commands 命令系统（最常用）

### 1.1 四步走的标准流程

1. Rust 端写一个带 `#[tauri::command]` 宏的函数
2. 把这个函数注册进 `lib.rs` 的 `generate_handler![]` 里
3. Rust 端改完后要等一下，让项目重新编译（终端输出 `Finished`）
4. 前端用 `import { invoke } from '@tauri-apps/api/core'`，`await invoke('函数名snake_case', { 参数名: 值 })`

### 1.2 完整最小示例：查询天气（同步命令 + 结构体参数 + 结构体返回）

**① Rust：`src-tauri/src/commands/weather.rs`**

```rust
use serde::{Deserialize, Serialize};

#[derive(Deserialize)]
pub struct WeatherQuery {
    pub city: String,
    pub days: u32,    // 查几天的
}

#[derive(Serialize)]
pub struct DailyWeather {
    pub date: String,
    pub high: i32,
    pub low: i32,
    pub condition: String,
}

#[derive(Serialize)]
pub struct WeatherResult {
    pub city: String,
    pub days: Vec<DailyWeather>,
}

#[tauri::command]
pub fn query_weather(query: WeatherQuery) -> Result<WeatherResult, String> {
    // 1. 校验
    if query.city.is_empty() {
        return Err("城市不能为空".into());
    }
    if query.days == 0 || query.days > 7 {
        return Err("天数必须在 1-7 天之间".into());
    }

    // 2. 干活（真实场景是调气象 API）
    let mut days = Vec::new();
    for i in 0..query.days {
        days.push(DailyWeather {
            date: format!("2026-08-{}", 27 + i),
            high: 28 + i as i32 % 5,
            low:  18 + i as i32 % 4,
            condition: match i % 3 {
                0 => "晴".into(),
                1 => "多云".into(),
                _ => "小雨".into(),
            },
        });
    }

    Ok(WeatherResult { city: query.city, days })
}
```

**② Rust：注册到 `lib.rs`**（省略导入语句）

```rust
pub mod commands {
    pub mod weather;
}
use commands::weather::query_weather;

pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![
            query_weather,
            // 其他命令继续加在数组里，用逗号分隔
        ])
        .run(tauri::generate_context!())
        .expect("error running tauri");
}
```

**③ 前端 TS 调用**

```ts
import { invoke } from '@tauri-apps/api/core'

interface DailyWeather {
  date: string
  high: number
  low: number
  condition: string
}
interface WeatherResult {
  city: string
  days: DailyWeather[]
}

// 组件里
const query = async () => {
  try {
    const result = await invoke<WeatherResult>('query_weather', {
      query: {
        city: '北京',
        days: 5,
      },
    })
    console.log(result.city, result.days.length) // 北京 5
  } catch (e) {
    // 错误就是 Rust 端 Err(xxx) 返回的那个字符串
    console.error('查天气失败:', e)
  }
}
```

**④ 常见坑：**
- ❌ Rust 函数名是 camelCase？No，必须 snake_case。`invoke('queryWeather', ...)` 会报错找不到命令。
- ❌ 注册漏了？把 `query_weather` 写进 `generate_handler![]` 了吗？没写一定报错 `command not registered`。
- ❌ 结构体字段漏 `pub`？所有要被 serde 序列化或 Tauri 注入的字段必须是 `pub`，不然编译就骂你。

### 1.3 完整示例：大文件转码（异步命令 + 事件回推进度）

同步命令会阻塞主进程。**任何耗时超过 100ms 的命令，都要写成 async。**

```rust
// Rust
use std::time::Duration;
use tokio::time::sleep;
use tauri::{AppHandle, Emitter};

#[tauri::command]
pub async fn transcode_file(
    app: AppHandle,
    file_path: String,
    quality: u32,
) -> Result<String, String> {
    if file_path.is_empty() {
        return Err("文件路径为空".into());
    }

    let steps: u32 = 20;
    for i in 1..=steps {
        // 模拟处理一帧/一片段
        sleep(Duration::from_millis(80)).await;

        // 👉 关键：向所有窗口实时推送进度
        let percent = ((i as f64) / (steps as f64) * 100.0) as u32;
        app.emit(
            "transcode-progress",
            serde_json::json!({
                "file": file_path,
                "current": i,
                "total": steps,
                "percent": percent,
            }),
        )
        .map_err(|e| e.to_string())?;
    }

    Ok(format!("{} 转码完成（画质={}）", file_path, quality))
}
```

前端：

```ts
import { invoke } from '@tauri-apps/api/core'
import { listen } from '@tauri-apps/api/event'

let unlistenProgress: Awaited<ReturnType<typeof listen>> | null = null

onMounted(async () => {
  // 先监听进度事件
  unlistenProgress = await listen<{
    file: string
    current: number
    total: number
    percent: number
  }>('transcode-progress', (evt) => {
    console.log(`进度: ${evt.payload.percent}%`)
  })
})
onUnmounted(() => unlistenProgress?.())

const start = async () => {
  // 再触发转码
  const result = await invoke<string>('transcode_file', {
    filePath: 'D:/video/big_buck_bunny.mp4',
    quality: 720,
  })
  console.log(result)
}
```

> 重要：**先 listen，后 invoke。** 如果你先调 invoke 再 listen，Rust 端很快的几步进度事件会在你监听之前就发了，你看不到，误以为「进度条从 0 一下跳到 30%」。

## 2. Events 事件系统（三种方向的完整最小示例）

事件跟命令的区别是**没有返回值**，就像你喊了一声，有没有人听到、听到后干什么，你不管。

### 2.1 Rust → 前端推送（上一节转码已经展示过一次了，这里补另一个常见场景：系统监听）

**Rust 侧用 `app.emit` 或 `window.emit`，前者发给所有窗口，后者发给指定。**

```rust
// Rust：模拟一个系统剪贴板监控器（在 setup 里启动一个后台线程）
use tauri::{App, Manager, Emitter};

pub fn setup_monitor(app: &mut App) -> Result<(), Box<dyn std::error::Error>> {
    let handle = app.handle().clone();

    // 启一个后台 task，每 5 秒广播一次"系统时间"
    tauri::async_runtime::spawn(async move {
        loop {
            tokio::time::sleep(Duration::from_secs(5)).await;
            let _ = handle.emit(
                "heartbeat-time",
                chrono::Local::now().format("%H:%M:%S").to_string(),
            );
        }
    });

    Ok(())
}

// 别忘了在 lib.rs 的 .setup(|app| { setup_monitor(app)?; Ok(()) })
```

前端监听：

```ts
import { listen } from '@tauri-apps/api/event'

const unlisten = await listen<string>('heartbeat-time', (e) => {
  console.log('收到心跳:', e.payload)
})
```

### 2.2 前端 → Rust 监听（你想在 Rust 收到一个「广播」时做什么事）

```rust
// Rust：setup 里注册监听
use tauri::{Listener, App};

pub fn setup(app: &mut App) -> Result<(), Box<dyn std::error::Error>> {
    let h = app.handle().clone();
    h.listen("user-logged-in", move |evt| {
        println!("[后端收到登录事件] payload = {:?}", evt.payload());
        // 比如去数据库把这个用户标记为在线、开 WebSocket 连接等
    });
    Ok(())
}
```

```ts
// 前端：登录成功时广播一下
import { emit } from '@tauri-apps/api/event'

await emit('user-logged-in', { userId: 123, userName: 'Tom' })
```

**什么时候用前端→Rust emit，而不是 invoke？**
- invoke：我要拿个返回值回来，或者我需要明确知道成功失败
- emit：我就是「吼一声」，不关心谁听到，也不想等结果

### 2.3 窗口 ↔ 窗口（多窗口消息）

两个窗口 label 分别是 `main`（主界面）和 `settings`（设置页）。

场景：设置窗口里改了字体大小，要让主窗口立刻重新渲染字号。

```ts
// 设置窗口（settings）里发送
import { emitTo } from '@tauri-apps/api/event'

const saveAndNotify = async () => {
  // 1. 先存配置到 store
  // ...
  // 2. 通知主窗口
  await emitTo('main', 'config-updated', {
    fontSize: 18,
    theme: 'dark',
  })
}
```

```ts
// 主窗口（main）里监听
import { getCurrentWindow } from '@tauri-apps/api/window'

await getCurrentWindow().listen<{ fontSize: number; theme: string }>(
  'config-updated',
  (e) => {
    document.documentElement.style.fontSize = e.payload.fontSize + 'px'
    applyTheme(e.payload.theme)
  },
)
```

> 发事件的 4 个 API 速记：
> - `emit()` → 所有人都能收到（所有窗口 + Rust 那边的 listen）
> - `emitTo('label')` → 只给指定 label 的窗口
> - `app.emit(...)`（Rust 侧）→ Rust 给所有窗口发
> - `window.emit_to("label", ...)`（Rust 侧）→ Rust 给指定 label 的窗口发

## 3. State 全局状态（跨命令共享内存数据）

典型需求：所有命令都要访问同一个数据库连接、同一个 App 配置、同一个当前登录用户。**不要每个命令都去打开一次数据库。** 用 `tauri::Builder::default().manage(...)` 把一个状态对象注入，所有命令的参数里写 `state: State<T>` 就能拿到。

### 3.1 完整示例：全局计数器 + 多命令共享

```rust
// Rust
use std::sync::Mutex;
use tauri::State;

// 定义你的状态结构体，想放多少字段放多少
pub struct GlobalState {
    pub counter: Mutex<i32>,   // Mutex 表示可互斥修改（多线程安全）
    pub app_started_at: String,
}

#[tauri::command]
pub fn inc_counter(state: State<GlobalState>) -> Result<i32, String> {
    // lock() 拿互斥锁，防止两个命令同时改（Mutex 的设计）
    let mut c = state.counter.lock().map_err(|e| e.to_string())?;
    *c += 1;
    Ok(*c)
}

#[tauri::command]
pub fn get_counter(state: State<GlobalState>) -> i32 {
    *state.counter.lock().unwrap()
}

pub fn run() {
    tauri::Builder::default()
        // 👉 第一步：启动时把状态注入
        .manage(GlobalState {
            counter: Mutex::new(0),
            app_started_at: chrono::Local::now().to_rfc3339(),
        })
        // 👉 第二步：命令里写 state: State<GlobalState> 参数
        .invoke_handler(tauri::generate_handler![inc_counter, get_counter])
        .run(tauri::generate_context!())
        .expect("error");
}
```

前端连续调：

```ts
await invoke('inc_counter')   // → 1
await invoke('inc_counter')   // → 2
await invoke('get_counter')   // → 2
```

### 3.2 状态存放什么合适

✅ **适合放 State 的：**
- 数据库连接池 / SQLite 句柄 / 已打开的文件句柄
- 应用配置（解析好的 struct，避免每次命令都读磁盘解析 JSON）
- 当前用户会话（token / userId / 权限）
- 缓存（最近 100 条查询结果）
- 所有命令共享的后台任务句柄

❌ **不要放 State 的：**
- 跟单次调用有关的临时数据（这是参数，不是全局状态）
- 前端 UI 状态（Pinia/Zustand/Redux 管去，别放 Rust 这边）
- 超大体积缓存（几 GB 那种，放磁盘，不要占内存）

## 4. 多窗口管理：创建、切换、传参

### 4.1 在 Rust 端动态创建新窗口

典型场景：用户在主界面点「设置」按钮，弹一个独立的设置窗口。

```rust
// Rust 命令
use tauri::{AppHandle, Manager, WebviewWindowBuilder, WebviewUrl};

#[tauri::command]
pub fn open_settings_window(app: AppHandle, initial_tab: Option<String>) -> Result<(), String> {
    // 1. 先查有没有已经打开的，有的话直接切过去不重复开
    if let Some(w) = app.get_webview_window("settings") {
        w.show().map_err(|e| e.to_string())?;
        w.set_focus().map_err(|e| e.to_string())?;
        // 并且把初始 tab 用事件发过去
        let _ = w.emit("settings-tab", initial_tab.unwrap_or_else(|| "general".into()));
        return Ok(());
    }

    // 2. 没有就新建
    WebviewWindowBuilder::new(
        &app,
        "settings",                          // label，窗口的唯一 ID
        WebviewUrl::App("/settings".into()), // 前端路由地址（相对路径）
    )
    .title("设置")
    .inner_size(720.0, 560.0)
    .min_inner_size(560.0, 420.0)
    .center()
    .resizable(true)
    .decorations(true)
    .build()
    .map_err(|e| format!("打开设置窗口失败: {}", e))?;

    Ok(())
}
```

前端点按钮：

```ts
await invoke('open_settings_window', { initialTab: 'account' })
```

### 4.2 窗口生命周期事件（打开/关闭/获得焦点/失焦）

```ts
const win = getCurrentWindow()

const unl1 = await win.onCloseRequested(({ payload }) => {

  console.log('窗口大小变了', size.width, size.height)

```

## 5. 综合实战：把上面四种全串起来的完整例子

**需求：**
1. 前端点「开始批量扫描文件」按钮，调 Rust 命令 `scan_folder(path: String)`
2. Rust 端 100ms 扫一个文件，实时 `emit` 进度给前端
3. 扫描完把所有发现的问题文件存进 `GlobalState.scan_result`（全局状态）
4. 扫描完成后，自动弹一个「扫描报告」新窗口（label=report）
5. 报告窗口里通过 `get_scan_result()` 命令读全局状态，显示列表

### ① Rust 端

```rust
use serde::{Deserialize, Serialize};
use std::sync::Mutex;
use std::time::Duration;
use tauri::{AppHandle, Emitter, Manager, State, WebviewUrl, WebviewWindowBuilder};
use tokio::time::sleep;
use walkdir::WalkDir;

#[derive(Serialize, Clone)]
pub struct ScanIssue {
    pub file: String,
    pub reason: String,
}

pub struct ScanState {
    pub last_result: Mutex<Vec<ScanIssue>>,
}

#[tauri::command]
pub async fn scan_folder(
    app: AppHandle,
    state: State<'_, ScanState>,
    folder: String,
) -> Result<u32, String> {
    // 1. 列出目录下所有文件
    let files: Vec<_> = WalkDir::new(&folder)
        .into_iter()
        .filter_map(|e| e.ok())
        .filter(|e| e.file_type().is_file())
        .collect();
    let total = files.len() as u32;
    if total == 0 {
        return Err("目录下没有文件".into());
    }

    let mut issues = Vec::new();

    for (idx, entry) in files.iter().enumerate() {
        sleep(Duration::from_millis(80)).await;
        let path = entry.path().display().to_string();

        // 假设的规则：文件 > 100MB 或扩展名是 .tmp 就算有问题
        let size = entry.metadata().map(|m| m.len()).unwrap_or(0);
        let ext = entry
            .path()
            .extension()
            .and_then(|e| e.to_str())
            .unwrap_or("");
        if size > 100 * 1024 * 1024 || ext.eq_ignore_ascii_case("tmp") {
            issues.push(ScanIssue {
                file: path.clone(),
                reason: if size > 100 * 1024 * 1024 {
                    format!("文件过大({}MB)", size / 1024 / 1024)
                } else {
                    "临时文件".into()
                },
            });
        }

        // 推进度
        let _ = app.emit(
            "scan-progress",
            serde_json::json!({
                "current": idx + 1,
                "total": total,
                "percent": ((idx + 1) as f64 / total as f64 * 100.0) as u32,
                "file": path,
            }),
        );
    }

    // 2. 结果保存到全局状态
    *state.last_result.lock().map_err(|e| e.to_string())? = issues.clone();

    // 3. 自动打开报告窗口
    if app.get_webview_window("report").is_none() {
        let _ = WebviewWindowBuilder::new(
            &app,
            "report",
            WebviewUrl::App("/report".into()),
        )
        .title("扫描报告")
        .inner_size(900.0, 600.0)
        .center()
        .build();
    }

    Ok(issues.len() as u32)
}

#[tauri::command]
pub fn get_scan_result(state: State<'_, ScanState>) -> Vec<ScanIssue> {
    state.last_result.lock().unwrap().clone()
}

pub fn run() {
    tauri::Builder::default()
        .manage(ScanState {
            last_result: Mutex::new(Vec::new()),
        })
        .invoke_handler(tauri::generate_handler![scan_folder, get_scan_result])
        .run(tauri::generate_context!())
        .expect("error");
}
```

### ② 主界面（MainView.vue）

```vue
<script setup lang="ts">
import { onMounted, onUnmounted, ref } from 'vue'
import { invoke } from '@tauri-apps/api/core'
import { listen, type UnlistenFn } from '@tauri-apps/api/event'
import { open } from '@tauri-apps/plugin-dialog'

const scanning = ref(false)
const percent = ref(0)
const currentFile = ref('')
const issueCount = ref(0)
let unlisten: UnlistenFn | null = null

onMounted(async () => {
  unlisten = await listen<{
    current: number
    total: number
    percent: number
    file: string
  }>('scan-progress', (e) => {
    percent.value = e.payload.percent
    currentFile.value = e.payload.file
  })
})
onUnmounted(() => unlisten?.())

const start = async () => {
  const folder = await open({ directory: true, title: '选择要扫描的目录' })
  if (!folder || typeof folder !== 'string') return

  scanning.value = true
  try {
    issueCount.value = await invoke<number>('scan_folder', { folder })
    alert(`扫描完成，发现 ${issueCount.value} 个可疑文件！已打开报告窗口`)
  } catch (e) {
    alert('扫描失败: ' + e)
  } finally {
    scanning.value = false
  }
}
</script>

<template>
  <div>
    <button :disabled="scanning" @click="start">
      {{ scanning ? `扫描中 ${percent}%` : '开始扫描目录' }}
    </button>
    <p v-if="scanning">正在处理：{{ currentFile }}</p>
  </div>
</template>
```

### ③ 报告窗口页面（ReportView.vue）

```vue
<script setup lang="ts">
import { onMounted, ref } from 'vue'

interface ScanIssue {

</template>
```

这个综合例子里：**命令**（scan_folder / get_scan_result）→ **事件**（scan-progress 推送）→ **状态**（ScanState 全局存结果）→ **多窗口**（report 报告窗口），四种通信机制全用到了。你把这个例子跑通一遍，Tauri 前后端通信的 95% 场景都能覆盖。
