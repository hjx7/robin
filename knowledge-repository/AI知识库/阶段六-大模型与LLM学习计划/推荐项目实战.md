# 阶段六：大模型与 LLM 推荐实战项目

> 配合《学习计划.md》使用，每个 Module 配套 1-2 个实战项目，由浅入深。

## 项目一：本地运行开源大模型对话 Demo（Module 2）

**难度**：⭐
**预计工时**：1-2 天

**目标**：在本地（或 Colab）跑通一个开源大模型，实现多轮对话。

**技术栈**：
- Python + HuggingFace Transformers
- 模型：Qwen2-1.5B 或 ChatGLM3-6B（视显存选择）
- 可选：bitsandbytes 4bit 量化

**实现步骤**：
1. 安装 transformers、accelerate、bitsandbytes
2. 使用 `AutoModelForCausalLM.from_pretrained` 加载模型
3. 使用 `AutoTokenizer` 加载分词器
4. 实现多轮对话函数（维护 history）
5. 调整采样参数（temperature、top_p）观察输出变化

**验收标准**：
- 能在终端进行多轮对话
- 能保存对话历史
- 能切换不同采样参数

## 项目二：垂直领域 LoRA 微调（Module 3）

**难度**：⭐⭐
**预计工时**：3-5 天

**目标**：使用 LoRA 在特定领域（如医疗/法律/客服）数据集上微调模型。

**技术栈**：
- LLaMA-Factory（推荐）或 PEFT 库
- 模型：Qwen2-1.5B 或 LLaMA3-8B
- 数据：BELLE 中文指令数据（子集）

**实现步骤**：
1. 准备数据集，转换为 alpaca 格式
2. 配置 LoRA 参数（rank=8, alpha=16, dropout=0.05）
3. 启动 LLaMA-Factory WebUI 训练
4. 训练完成后合并权重
5. 对比微调前后模型在测试集上的表现

**验收标准**：
- 训练 loss 正常下降
- 微调后模型在垂直领域问答质量明显提升
- 能导出合并后的模型权重

## 项目三：企业知识库 RAG 问答系统（Module 5）

**难度**：⭐⭐⭐
**预计工时**：5-7 天

**目标**：搭建一个基于私有文档的问答系统，解决大模型「幻觉」与「知识滞后」问题。

**技术栈**：
- LangChain 或 LlamaIndex
- 向量数据库：Chroma（入门）/ Milvus（生产）
- Embedding：bge-large-zh
- LLM：Qwen2 或通过 API 调用 GPT-4

**实现步骤**：
1. 文档加载：支持 PDF、Word、Markdown
2. 文档切分：RecursiveCharacterTextSplitter（chunk=500, overlap=50）
3. 向量化：使用 bge 模型生成 embedding
4. 入库：存入 Chroma / Milvus
5. 检索：相似度检索 Top-K（K=5）
6. 生成：将检索结果拼入 Prompt 调用 LLM
7. 进阶：加入 Rerank、多路召回、对话上下文管理

**验收标准**：
- 支持上传 PDF/Word/MD 文档
- 检索准确率 > 80%
- 能引用原文片段作为答案依据
- 支持多轮对话

## 项目四：具备工具调用能力的 Agent（Module 5）

**难度**：⭐⭐⭐
**预计工时**：5-7 天

**目标**：开发一个能调用外部工具完成复杂任务的 Agent。

**技术栈**：
- LangGraph 或 LangChain Agent
- 工具：搜索（Tavily/SerpAPI）、计算器、天气查询、代码执行
- LLM：支持 Function Calling 的模型

**实现步骤**：
1. 定义 3-5 个工具函数（搜索、计算、天气、SQL 查询等）
2. 使用 LangGraph 构建状态机 Agent
3. 实现 ReAct 循环：Thought → Action → Observation → Answer
4. 增加记忆模块：保存对话历史
5. 增加 Planning：复杂任务自动拆解

**验收标准**：
- Agent 能根据问题自主选择工具
- 能完成多步推理任务（如「查北京今天天气，然后计算摄氏度转华氏度」）
- 能处理工具调用失败的情况

## 项目五：实现一个 MCP Server（Module 5）

**难度**：⭐⭐⭐
**预计工时**：3-5 天

**目标**：使用 MCP 协议开发一个标准化的工具服务，可被 Claude Desktop / Cursor 等 Host 调用。

**技术栈**：
- MCP Python SDK 或 TypeScript SDK
- 工具主题可选：
  - 文件系统 MCP Server
  - 数据库查询 MCP Server
  - 内部知识库检索 MCP Server

**实现步骤**：
1. 阅读 MCP 官方规范，理解 Client/Server/Host 架构
2. 使用 Python SDK 创建 MCP Server
3. 定义 Tools（至少 3 个工具）
4. 可选：定义 Resources 和 Prompts
5. 在 Claude Desktop 配置中注册该 Server
6. 测试 Claude 调用你的工具

**验收标准**：
- MCP Server 可独立启动
- 能被 Claude Desktop 正确识别
- 工具调用链路通畅，返回结果正确

## 项目六：Skills 能力封装包（Module 5）

**难度**：⭐⭐
**预计工时**：2-3 天

**目标**：将一组通用能力封装为 Skills 模块，供 Agent 按需调用。

**实现内容**：
1. 设计 Skills 描述规范（名称、用途、入参、出参、示例）
2. 实现 3-5 个常用 Skills：
   - `summarize_document`：文档总结
   - `generate_code`：代码生成
   - `query_database`：数据查询
   - `translate_text`：文本翻译
3. 实现 Skills 注册与发现机制
4. 在 Agent 中集成 Skills 调用

**验收标准**：
- 每个 Skill 有清晰的描述规范
- Agent 能根据任务自动选择合适的 Skill
- Skills 之间可组合使用

## 项目七：使用 vLLM 部署模型 API 服务（Module 6）

**难度**：⭐⭐
**预计工时**：2-3 天

**目标**：将微调后的模型部署为高性能 API 服务。

**技术栈**：
- vLLM
- FastAPI（可选，作为 API 网关）
- Docker（容器化部署）

**实现步骤**：
1. 安装 vLLM：`pip install vllm`
2. 启动服务：`python -m vllm.entrypoints.openai.api_server --model <model_path>`
3. 兼容 OpenAI API 格式，可直接使用 OpenAI SDK 调用
4. 使用压测工具测试 QPS、延迟
5. 使用 Docker 打包镜像
6. 可选：使用 Nginx 做负载均衡

**验收标准**：
- 服务稳定运行，支持并发
- 接口兼容 OpenAI API 格式
- 单卡 QPS 达到合理水平
- 完成 Docker 镜像打包

## 综合项目：构建一个完整的「智能助手」产品（可选挑战）

**难度**：⭐⭐⭐⭐
**预计工时**：2-3 周

**整合所有能力**：将前面 7 个项目的成果整合为一个完整产品。

**功能要求**：
1. 基于 RAG 的知识库问答（项目三）
2. Agent 工具调用能力（项目四）
3. 通过 MCP 暴露能力（项目五）
4. Skills 模块化封装（项目六）
5. vLLM 后端部署（项目七）
6. 简单的 Web UI（可用 Streamlit / Gradio）

**产出**：
- GitHub 开源仓库
- 完整 README + 架构图
- 在线 Demo（可选）
- 技术博客

---

## 项目实战建议

1. **按顺序推进**：项目难度递增，每个项目依赖前一个的产出
2. **保留代码**：每个项目的代码沉淀到 GitHub，形成作品集
3. **写文档**：每个项目都要有 README，记录思路与踩坑
4. **不要追求完美**：先跑通 MVP，再迭代优化
5. **对比方案**：如 RAG 项目可同时实现 LangChain 和 LlamaIndex 版本对比
